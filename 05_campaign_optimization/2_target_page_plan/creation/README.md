# ② 施策｜施策作成エージェント（対象ページ選定＋改善案）

> 全体方針の中で「どのページを、どう変えるか」を精査して決める。

| 項目 | 内容 |
|---|---|
| レイヤー | ② 施策（対象ページ選定＋改善案） |
| データソース | GA4 API（クライアント非依存で統一。BigQuery は V2 送り） |
| ステータス | プロトタイプ実装済み（prompts/create-page-plan.md） |

## 役割
全体方針（例: LPO）を受け、対象候補ページを GA データと page_profile（ページの目的/ターゲット）を踏まえて精査し優先ページを決めたうえで、選んだページのHTML・モバイルFVを実際に見て「どこを・どう変えるか」の改善案まで出す。パターン作成前に検出力を判定し、必要サンプルが集まらないページではA/Bテストを強行せず、計測先行または単一案リリースへ分岐する。

**旧・個別施策（対象ページ選定のみ）と旧・ABテスト施策作成（改善案）を統合したエージェント。** 統合の理由: 「どう変えられるか」を考えずにページは選べない（改善案を作る段になって初めて「テストの検出力が足りない」等が分かるケースがあり、選定の段で気づけないと手戻りになる）。詳細は `../README.md`。

## 入力
- 全体方針（①の出力）
- page_profile の出力（各ページが誰向け・どの目的か）
- `05/2_target_page_plan/analysis` の分析結果（ページ別の事実。検算済み）
- 対象ページのHTML/構造（選定後に取得。モバイルFVはPlaywrightで撮影）

## 出力（スコープ）
**対象ページの決定＋改善案（方向性＋複数コピー/UI案）まで**。確定原稿・デザインは人が最終調整。
出力は必ず「## 対象ページ選定」と「## 改善案（ページごと）」を別セクションに分けて書く（後続のレビューが選定と案を別々に判定できるようにするため。詳細は `prompts/create-page-plan.md`）。

## 連携
page_profile に依存 / creation_review でレビュー（選定・改善案を別々に判定）→ 確定後は人が実装・テスト実行
