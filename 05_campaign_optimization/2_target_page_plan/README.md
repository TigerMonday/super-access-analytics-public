# ② 施策｜フロー（05側、対象ページ選定＋改善案）

①で決まった改善タイプ（例: LPO）の中で、**どのページを、どう変えるか**を決める。
**05が分析と施策作成（する側）、06がそのレビュー（検証する側）**。
肝は **ページの目的を見て、CV率が低いだけのページに飛びつかないこと**。

**旧構成では「②個別施策（対象ページ選定のみ）」と「③ABテスト（改善案）」に段が分かれていたが、
統合した。** 理由: 「どう変えられるか」を考えずにページは選べない（改善案作りの段で初めて
「このページはテスト対象として検出力が足りない」等が分かり、選定段階まで差し戻す手戻りが
実際に起きた）。段をまたぐたびに同じ内容が書き写され、そのたびに壊れる機会も増える
（例: 到達率の定義が分析では表を分けて解決していたのに、対象ページ選定で1表にまとめ直す
際に混在が再発した）。統合後は選定と改善案を1回の分析・レビューサイクルで行い、選定だけ・
改善案だけの手戻りは「出力の中のセクション単位」で行う（下記「フロー」参照）。

## フロー（4エージェント＋前提）

| 順 | エージェント | 場所 | 出力 |
|---|---|---|---|
| 0 | （前提）ページ目的判定 | `../page_profile/` | page-profile（誰向け・目的） |
| 1 | **分析** | `analysis/`（05） | 05-page-analysis（ページ別の事実） |
| 2 | 分析レビュー | `../../06_effect_verification/2_target_page_plan/analysis_review/` | 06-…-review（検算） |
| 3 | **施策作成（対象ページ選定＋改善案）** | `creation/`（05） | 07-target-page-plan（対象ページ＋改善案） |
| 4 | 施策レビュー（選定・改善案を別々に判定） | `../../06_effect_verification/2_target_page_plan/creation_review/` | 08-…-final（確定） |

- 起動・データ取得は **05/2_target_page_plan/analysis** から（`analysis/run.md` あり）
- `page_profile` を前提に走らせる（または分析内で当てる）
- 全ページ行は保存し、個別分析は原則としてセッション累積80%まで（最大50ページ）に、CV発生・登録済みCV直結・有料流入LPを追加する
- 途中成果物（`05〜08`）は `outputs/{client}/05_cvr/_past/` に `05-page-analysis → 06-page-analysis-review → 07-target-page-plan → 08-target-page-plan-final` の順で残る（チェーンの現在地判定もここで行う）。`08-target-page-plan-final` が確定したら、その内容は `outputs/{client}/05_cvr/cvr-improvement-plan.md` へ直接反映する。**クライアント向け確定版はこの1本だけで、段ごとの個別確定版は作らない**（docs/standard-run-order.md §4-5）
- `07-target-page-plan.md` は「## 対象ページ選定」「## 改善案（ページごと）」の2セクションに分けて書く。06のレビューはこの2セクションを別々に判定し、差し戻すときも「選定のみ」「改善案のみ」「両方」のどれかを明示する（下記「選定と改善案を分けて判定する」）
- 改善案を複数作る前に検出力を計算する。期間内に判定できる場合だけA/Bテストを行い、データ不足なら計測整備、必要期間が長すぎる場合は単独リリース＋前後比較へ切り替える

## スコープ
出すのは**対象ページの決定＋改善案（方向性＋複数のコピー/UI案）**まで。確定原稿・デザインは人が最終調整。
- 「どの改善タイプか」← ① 全体施策（前提）

## 優先順位ロジック（選定）
**CV直結度 × 規模 × 改善余地**。生CV率ワーストでは選ばない（認知用ページは元々低い）。
エンゲージ率は選定・優先順位・成果物に使わない。離脱は定義済み指標が無ければ「計測不能」とする。

## 選定と改善案を分けて判定する
統合後も「対象ページの選び方が正しいか」と「改善案の中身が正しいか」は別の問題であり、
案の出来で選定の評価が引きずられる（またはその逆）のを防ぐ。`creation/prompts/create-page-plan.md`
は出力を2セクションに分けて書き、`creation_review/prompts/review.md` はその2セクションを
それぞれ独立に「妥当／要修正」判定する。組み合わせは次の4通り:

| 選定 | 改善案 | 次の動き |
|---|---|---|
| 妥当 | 妥当 | 確定版へ反映 |
| 要修正 | 妥当（保留） | 選定のみ05へ差し戻す。改善案は選定確定後に対象ページが変わりうるため保留し、選定確定後に再判定する |
| 妥当 | 要修正 | 改善案のみ05へ差し戻す（選定はそのまま） |
| 要修正 | 要修正 | 両方05へ差し戻す |
