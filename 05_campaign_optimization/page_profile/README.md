# ページプロファイル｜専用エージェント（インプット元②）

> 各ページが「誰向け・どの目的（認知/ナーチャリング/CV直結）か」を判定する。

| 項目 | 内容 |
|---|---|
| レイヤー | 支援（② 施策の前提） |
| データソース | GA4 API＋ページ回遊・コンテンツ取得 |
| ステータス | プロトタイプ実装済み（prompts/profile.md） |

## 役割
②施策（対象ページ選定＋改善案）の精査に必須の前提情報を作る。サイト/LPの各ページを回遊・分析し、ターゲットと目的を判定。クライアントに毎回聞くと時間がかかるため、可能な範囲をAIで補完し、不足は対話で投げ返す。

## 入力
対象サイトのURL群 / GA4データ / 01コンテキスト（profile・ターゲット）

## 出力（スコープ）
ページ別プロファイル（誰向け・目的・流入元クリエイティブとの整合）

- GA4の全ページ行は生データとして保存する
- 個別に本文を読んで判定する標準範囲は、セッション累積80%まで（最大50ページ）
- CV発生ページ、登録済みCV直結ページ、有料流入のランディングページは標準範囲外でも追加する
- Web根拠は取得日・URL・確認内容が追えるスナップショットとして `_data/page_profile/` に残す
- エンゲージ率はページ目的や優先順位の判定に使わない
- 冒頭に「使った前提」を置き、`barrier_id` / `stimulus_id` は一致IDまたは「該当なし」を明記する

## 連携
2_target_page_plan/creation の入力になる
