# レポート可視化ガイド

アクセス解析・市場調査・顧客理解・施策提案の全レポートで、表・グラフ・図解を選ぶときの正本。
見栄えのために図を増やすのではなく、読み手に何を比べ、何を判断してほしいかから選ぶ。

## 選定手順

1. その面で伝える結論を1文で書く。
2. 根拠が定量データか定性情報かを分ける。
3. 下表から「読み手にさせたいこと」に合う見せ方を1つ選ぶ。
4. グラフ化で正確さが落ちる場合は、表または文章を選ぶ。図を置くこと自体を目的にしない。
5. タイトルは「月次推移」のような項目名だけではなく、「自然検索の減少が全体を押し下げた」のように対象と読み取りを直接書く。根拠が弱い場合は断定せず「減少の主因候補」のように区別する。

## 目的から選ぶ

| 読み手にさせたいこと | データ・情報の形 | 既定の見せ方 | 避ける見せ方 |
|---|---|---|---|
| 時間による変化を見る | 日・週・月など連続した値 | 折れ線。量の大小を強調する1系列なら棒 | 合計値を時系列の1点として混ぜる |
| 桁や単位が違う指標の推移を比べる | セッション・CV・CVRなど | セッションは単独。同じKPIのCV数（棒）とCVR（折れ線）は左右の独立軸で同一パネルに重ねる | 異なる単位を同じ縦軸へ重ねる、CV数と対応するCVRを別々の小図に分断する |
| 項目間の大小・順位を見る | チャネル・ページ・競合など | 降順の横棒、またはセル内バー付き表 | ラベルと数値が離れた独立グラフ |
| 基準との差を見る | 前期差・目標差・増減率 | ゼロを基準にした差分棒、増減列つき表 | 現在値だけの円グラフ |
| 構成比を見る | 合計が100%になる内訳 | 100%積み上げ棒、少数カテゴリなら構成比表 | 母数不明の円・ドーナツ、細かい多数分類 |
| 正確な値を読む | 明細、複数指標、注記を含む値 | 右寄せ・同精度の表 | 色の濃淡だけで値を読ませる |
| 相関を見る | 同じ対象に対する2つの連続量 | 散布図 | 2本の折れ線を重ねて因果を示す |
| 分布を見る | 個票または十分な件数の値 | ヒストグラム、箱ひげ、ドット | 平均値だけの棒 |
| 段階と詰まりを見る | 検討・購入・フォームなど順序のある段階 | フロー図、ジャーニー図。実数があれば段階別表も併記 | 根拠のない漏斗形状 |
| 複数の定性軸を比べる | 競合モデル、顧客像、3C | 同じ列を使う比較表、交点図 | 根拠のない点数・レーダーチャート、色分けしたカードの羅列 |
| 仮説の確からしさを示す | 事実・自社発信・顧客の声・仮説 | 根拠状態の一覧表、色付きラベル | 仮説を数値化した疑似スコア |
| 優先順位を決める | 効果と工数など比較可能な2軸 | 2軸マトリクス。軸の根拠が弱ければ優先順位表 | 根拠なしに右上へ配置する図 |

## 市場・顧客レポート固有の既定

- 市場規模や成長率など比較可能な数字があるときだけ定量グラフを使う。単位・母集団が違う数字はKPIカードで個別に見せ、同じ棒グラフへ並べない。
- 3CはCustomer・Competitor・Companyと、その交点を示す。それぞれを別色のカードにせず、同じ紙面の表か平らな3列で比較する。各要素を恣意的に点数化しない。
- ペルソナが複数いる場合は、発火点・比較対象・不安・求める材料を同じ列で比較する。
- カスタマージャーニーは段階を横方向に並べ、各段階の「障壁」と「次へ進む刺激」をラベルで区別する。障壁は要対応の意味で赤、刺激は望ましい状態の意味で緑を使えるが、色が無くても読めるラベルを残す。
- 定性情報を棒・円・レーダーへ変換しない。数が無いものは比較表・カード・フロー図を使う。

## 表現とアクセシビリティ

- 複合グラフを縦に並べる場合、各段に見出しと区切り線を設ける。CV数とCVRは同じ段に重ね、各段に年月ラベルとX軸名を表示する。軸・年月ラベルはSVG座標で12px以上、段間は125以上を基本とし、別段のラベルと重ねない。数値の規模を読めるよう、棒の実数と縦軸の中間目盛りを表示する。割合の目盛りは丸め過ぎず、左右の系列名を明示する。
- 同じ表に複数のCVがある場合は、成立する「CV数・CVR」の組をすべて残す。`問い合わせ数` と `問い合わせCVR`、`申込完了数` と `申込CVR` のような実務上同じKPI名は同じ組として扱う。組にならないCVRを単独パネルへ逃がさず、HTML/PDF出力を停止して列名を直す。

- 1面につき主メッセージは1つ、主要な表または図は原則1つ。前置きは1〜3文にする。
- 数値セクションは根拠表、ラベルを付けない考察本文、グラフの順に配置する。同じ意味単位は同じ面に保ち、色を見分けられなくても表から同じ値を読めるようにする。
- 色は「良い結果」の緑と「悪い結果・要対応」の赤に意味を固定する。それ以外は白黒グレー、強調だけゴールドとする。チャネルや競合などの分類に別色を割り当てない。
- 増減は自動的に緑・赤へ変換しない。その増減がビジネス上よいか悪いか判断できるときだけ使う。
- 色だけに依存せず、文字ラベル・記号・並び順も併用する。
- ボックスの上辺・左辺に飾り線を付けない。囲み枠の代わりに余白、薄いグレー面、字の級差で情報をまとめる。
- 同じ大きさのカードを機械的に並べない。主結論は大きく、根拠は図表で、補足は小さくし、情報の重みを見た目に反映する。
- 数値列は右寄せ、桁区切り、列内で同じ小数桁にする。合計行はグラフに含めない。
- ランキング表には「合計」または「表示合計」を置き、全件合計と上位件数の小計を区別する。
- CVRなど計算値は、分子・分母・単位を表か直前の考察で明示する。

## Markdownから生成できる数値グラフ

表の直前にコメントを置く。表は根拠データとしてHTMLにも残る。

```markdown
<!-- chart: line; title: 相談CVは春以降に増加 -->
<!-- chart: bar; title: 自然検索が最大の流入源 -->
<!-- chart: combo; title: 流入減に対して相談CVRは維持 -->
<!-- chart: table-bars; title: チャネルごとの流入とCVを比較 -->
```

基本分析のように時系列または比較可能なカテゴリ値を持つレポートでは、`table-bars` だけで
終わらせず、少なくとも1つは `line` / `bar` / `combo` / `search` のいずれかを使う。
セル内バーは表を読みやすくする補助であり、独立したグラフの代わりには数えない。

## 主要レポートの完成条件

担当者や実行エージェントが変わっても見せ方が抜けないよう、クライアント向け主要4レポートには次の表現基準を置く。03・04・05は内容に合う可視化を確実に残すための契約とし、計測チェックは一覧表を正とする。

| レポート | 必須の見せ方 | 理由 |
|---|---|---|
| 計測チェック `check-report` | 判定・状態・確認根拠を並べた一覧表 | 件数グラフより、どの設定をなぜ確認・修正するかを読めることが重要 |
| 市場・顧客理解 `00_3c_persona_journey_report` | 顧客・市場の要点／競合・代替との違い／次の判断のピクトグラム要約 | 定性結論を疑似スコアにせず区別できる |
| 基本分析 `basic-analysis-report` | 期間を明記した比較表＋月次グラフ＋分析サマリーのピクトグラム要約。週次は本文へ出さない | 定量根拠と意思決定要点の両方が必要 |
| サイト改善 `cvr-improvement-plan` | 改善課題／優先施策／期待する変化のピクトグラム要約 | 施策の因果を根拠のない数値へ変換せず示せる |

HTMLまたはPDFを生成するときは、`report_export` が描画後のHTMLを検査する。条件を満たさない場合は古い形式の成果物を完成扱いにせず、Markdownの指定と直後の表を修正して再出力する。未変換の可視化指定と、単独パネルに残ったCVRも出力エラーとする。図表より前に読み方・考察がない固定面は品質チェックの読み直し候補にする。

## Markdownから生成できるピクトグラム要約

数値ではない2〜5個の並列要素を素早く見分けてもらう場合だけ、1行のMarkdown表の直前に
ピクトグラム名を指定する。HTMLでは同じ内容がピクトグラム付きの平らな要約へ変換され、
Markdownでは通常の表として読める。

```markdown
<!-- pictograms: issue,insight,target -->
| 課題 | 分かったこと | 次の判断 |
|---|---|---|
| 自然検索の減少 | 指名外クエリが主因候補 | 対象ページを確認する |
```

利用できる名前は `analysis`（分析）、`issue`（課題）、`insight`（示唆）、`target`（目標）、
`growth`（成長）、`verified`（検証済み）。チャート、数値表、単一の主結論には置かず、
要素が並ぶサマリーや「課題→示唆→次の行動」の区別に使う。1つの要約は最大5個とし、
上表で必須とした要約以外は、各レポートへ機械的に付けない。ピクトグラムはMaterial Symbols Roundedを元にした
Apache License 2.0の素材で、ライセンス全文は
`src/report_export/assets/pictograms/LICENSE` に保持する。ピクトグラムを使った単体HTMLには
可視の出典・ライセンスリンクと、NOTICE／ライセンス全文を自動で同梱する。PDF出力では
末尾のライセンス付録として全文を含める。
