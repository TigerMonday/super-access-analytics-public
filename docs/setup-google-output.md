# 成果物をGoogleドキュメント・スプレッドシートに出す（任意設定）

[GA4の初回セットアップ](./setup-ga4.md)を終えた人向けの追加設定です。レポートをGoogleドキュメントやスプレッドシートへ書き出せるようにします。

この設定は任意です。設定しなくても分析とローカルへの保存はできます。

## 事前に確認しておくこと

**サービスアカウント（分析ツールが使う専用のGoogleアカウント）は、自分でファイルを新しく作れない。** これはGoogleが公式に「サービスアカウントは保存容量を持たず、ファイルを所有できない」と説明している仕様で、回避策ではない。そのため手順は**「利用者が先に空のファイルを作り、サービスアカウントに編集者として共有し、その中に書き込んでもらう」**という形に固定される。この後の手順もすべてこの前提で進む。

ドメイン全体の委任（サービスアカウントが特定の人になりすませるようにする設定）は不要。これが必要になるのは人になりすます場合だけで、今回の用途には関係ない。

## 書き込むと何が起きるか（先に確認する）

設定すると、分析を実行するたびに次のように書き込まれる。**既存の内容を黙って消すことはない。**

- **スプレッドシートの場合**: 実行のたびに、日付名の新しいシート（タブ）が追加される。既存のシートには一切触れない。
- **ドキュメントの場合**: そのレポートに対応する見出し1の区画だけが差し替わる。区画外の文章はそのまま残る。**文書の末尾に「メモ」という見出し1を自分で作っておくと、それより下は分析ツールが絶対に書き換えない。** 気づいたことを書き留めておく欄として使える機能なので、使うなら最初に作っておくとよい。

## 全体の流れ

1. Google出力用のサービスアカウントと鍵を作る
2. Google Docs API・Google Sheets APIを有効にする
3. 空のドキュメント・スプレッドシートを作る
4. Google出力用サービスアカウントに共有する
5. AIにURLを伝える
6. 動作確認

## 1. Google出力用のサービスアカウントと鍵を作る

GA4の読み取り用アカウントへ編集権限を追加せず、Google出力専用のアカウントを使います。

1. [GA4セットアップの「サービスアカウントを作り、鍵ファイルを取得する」](./setup-ga4.md#2-サービスアカウントを作り鍵ファイルを取得する)と同じ操作で、新しいサービスアカウントを作ります。名前は`saa-google-export`など、GA4用と区別できるものにします。
2. JSON形式の鍵を取得します。
3. サービスアカウントのメールアドレス（`...iam.gserviceaccount.com`で終わるもの）を控えます。
4. AIに「ホームフォルダの`.saa/credentials/google-export`フォルダを作ってください」と頼みます。
5. 鍵をそのフォルダへ移し、`sa-key.json`に名前を変えます。

既定の保存先は`~/.saa/credentials/google-export/sa-key.json`です。別の場所を使う場合は、AIに`SAA_GOOGLE_EXPORT_SA_KEY_PATH`の設定を頼んでください。鍵はチャットやリポジトリへ入れません。

## 2. Google Docs API・Google Sheets APIを有効にする

[docs/setup-ga4.md](./setup-ga4.md) の手順5（Google Analyticsの機能をGCP側で有効にする）で開いたのと**同じGCPコンソールの同じ画面**を使う。プロジェクトを新しく作る必要はない。

1. [Google Cloud Console](https://console.cloud.google.com/) を開き、上部のプロジェクト名がGA4用に作ったプロジェクトになっているか確認する。
2. 検索バーに「Google Docs API」と入力して開き、「有効にする」をクリックする。
3. 同じ手順で「Google Sheets API」も検索して有効にする。

## 3. 空のドキュメント・スプレッドシートを作る

いつも使っているGoogleアカウントで、[Googleドキュメント](https://docs.google.com/document/)・[Googleスプレッドシート](https://docs.google.com/spreadsheets/)を開き、それぞれ新規で空のファイルを1つずつ作る。ファイル名はあとで見て分かるものにしておく（例:「〇〇サイト分析レポート」）。両方は要らず、使いたい方だけ作ってもよい。

## 4. Google出力用サービスアカウントに共有する

1. 手順3（空のドキュメント・スプレッドシートを作る）で作ったファイルを開き、右上の「共有」を押します。
2. 手順1（Google出力用のサービスアカウントと鍵を作る）で控えたメールアドレスを入力します。
3. 権限を「編集者」にして共有します。「閲覧者」では書き込めません。
4. 両方の形式を使う場合は、それぞれのファイルで共有します。

共有したファイルのURLを控えます。次の手順で使います。

## 5. AIにURLを伝える

控えたURLを、対応するAIエージェントにそのまま伝える。

```
Googleドキュメントは https://docs.google.com/document/d/xxxx/edit を使ってください
Googleスプレッドシートは https://docs.google.com/spreadsheets/d/xxxx/edit を使ってください
```

初めて設定するときは、成果物の書き出し先（Markdownのみか、HTML・PDF等に変換するか）を聞かれる流れの中で、このURLもあわせて確認される。すでに登録済みのサイトであとから追加する場合は、上記のように伝えれば設定に追記される。一度登録すれば、以後の実行では毎回このURLへ自動で書き出されるようになり、聞き直されることはない。

## 6. 動作確認

設定後、いずれかの分析（基本分析など）を実行すると、完了時の案内に書き込んだ先のURLが表示される。

- スプレッドシート側は、実行した日付が入った新しいシート（タブ）が増えている。
- ドキュメント側は、そのレポートに対応する見出し1の区画に内容が入っている（表は罫線付きの表としてそのまま読める形で入る）。

URLを開いて実際にこの状態になっていれば設定は完了。

## うまくいかないときの見分け方

| 症状 | 原因 | 対処 |
|---|---|---|
| 共有しようとしたら「外部のユーザーとは共有できません」のように弾かれる | 会社のGoogle Workspaceで社外への共有が禁止されている。サービスアカウントのメールアドレスは自社ドメインではないため、社外のアカウントとして扱われる | 情報システム部門に共有の許可を依頼する。依頼文の例:「分析ツールが使うサービスアカウント（`...iam.gserviceaccount.com`）は、社外のアカウントではなく自社のGoogle Cloudプロジェクト内で発行したものです。このアカウントに、指定のドキュメント／スプレッドシートを編集者として共有できるようにしてください」 |
| 鍵が見つからない | 手順1（Google出力用のサービスアカウントと鍵を作る）の保存先が違う | `~/.saa/credentials/google-export/sa-key.json`にあるか確認する |
| `Google Docs API has not been used in project ... before or it is disabled` / `Google Sheets API has not been used in project ...` | 手順2（Google Docs API・Google Sheets APIを有効にする）が終わっていない | 該当のAPIを有効にする。有効化した直後なら数分待って再試行する |
| 「書き込み先のGoogleドキュメント（またはスプレッドシート）が指定されていません」と表示される | 手順5（AIにURLを伝える）のURLが保存されていない | URLを伝え直し、保存されたかAIに確認する |
| `PERMISSION_DENIED` / `403` | 手順4（Google出力用サービスアカウントに共有する）の権限または共有先が違う | Google出力用のメールアドレスが「編集者」になっているか確認する |
| `Google出力(gdoc/gsheet)には追加の依存が必要です` のようなメッセージで止まる | Googleドキュメント・スプレッドシートへの書き出しに使う依存パッケージが入っていない | メッセージに書かれた `uv sync --extra google` をこのツールのフォルダ（`common/report_export`）で実行する |

これでも解決しない場合は、エラーメッセージ全文を控えたうえで確認する。証明書関連のエラー（`SSL_ERROR_SSL` 等）が出る場合は、[docs/setup-ga4.md](./setup-ga4.md) の「証明書のエラーが出るとき」がそのまま当てはまる。
