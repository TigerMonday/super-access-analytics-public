# AIが初回セットアップを案内する手順

利用者から「セットアップしたい」「初期設定をしたい」「GA4につなぎたい」「使える状態にして」と頼まれたときの共通手順です。AI製品に関係なく、この文書を正本として進めます。

## 完了の基準

次の4点を満たしたら、GA4の基本セットアップは完了です。

1. `uv`で付属サンプルを読み込める
2. Googleの鍵が正しい場所にあり、サービスアカウント鍵として読める
3. 利用者が選んだGA4プロパティへ管理用API・分析用APIの両方で接続でき、表示名とIDが一致する
4. サイト名、GA4プロパティID、確認済みのCVがサイトの登録情報に保存されている

GTM、Search Console、BigQueryは任意です。接続すると確認・分析できる内容が増えるため、GA4の確認後に3つまとめて希望を聞きます。

## 案内するときの決まり

- 最初にAI自身が状態を確認し、完了済みの作業は飛ばす
- 初回の案内には、[AIエージェント共通ガイドの問い合わせ窓口の案内](./ai-agent-guide.md#利用者への問い合わせ窓口の案内)に沿ってフォームのリンクを一度だけ添える
- コマンドはAIが実行する。利用者には、Googleの管理画面など本人にしかできない操作だけを頼む
- Pythonやライブラリなどをインストールするときは、何を何のために入れるかを先に説明し、利用者の許可を得てから実行する
- 同じ目的のインストールは一まとまりで説明し、一度の許可でまとめて行う。許可されていない別のツールや任意機能のライブラリを追加するときは、改めて許可を得る
- 一度に案内するのは、同じ画面で終えられる一まとまりまでにする。利用者が「できた」と答えたら状態を再確認する
- 鍵の中身や秘密鍵は、チャット・ログ・レポートへ表示しない
- 閲覧できるGA4プロパティをAIが勝手に選ばない。表示名とIDを示し、利用者の確認後に保存する
- GA4接続後は、GTM・Search Console・BigQueryを今回一緒に設定するか3つまとめて確認する。どれかを省略して聞かない
- エラーでは、鍵の作り直しから案内し直さず、止まっている箇所だけを説明する
- `01`や`02`などの内部番号、`client_id`などの内部名は利用者への説明に使わない

## 1. インストールせずに現在の状態を確認する

最初はファイルの読み取りと、既に入っているツールの確認だけを行います。`uv --version`を実行し、README.md、`docs/ai-agent-guide.md`、`tools/setup_status.py`があることを確認します。この段階では`uv sync`や`uv run`を実行しません。

`uv`が無い場合は、OSに合う導入方法と用途を説明し、許可を得てから[READMEのインストール手順](../README.md#install-tools)を案内します。会社のパソコンなど、利用者自身がインストールできない場合は管理者への依頼に切り替えます。

Pythonまたは必要なライブラリがまだ用意されていない可能性がある場合は、次のように許可を確認します。

```text
動作確認のため、このスーパーアクセス解析で使うPythonと必要なライブラリをパソコンへ用意します。まだ入っていないものはダウンロードされます。実行してよいですか？
```

利用者が許可したら、AIが次を実行します。`--locked`を付け、リポジトリで決められたバージョンだけを入れます。

```bash
uv sync --locked --project 01_context_management
uv sync --locked --project 02_basic_measurement/measurement_design
```

許可が得られない場合はインストールせず、付属サンプルとGoogle接続の動作確認は未完了として伝えます。

## 2. 設定状況を診断する

リポジトリのルートで、AIが次を実行します。

```bash
uv run --no-sync --project 01_context_management python tools/setup_status.py --json --run-sample-check
```

この診断は、作業フォルダ、`uv`、付属サンプル、Googleの鍵、保存済みのサイト情報を確認します。Search Console用の`SC_SA_KEY_PATH`やBigQuery用の`BQ_SA_KEY_PATH`があれば、その別鍵も確認します。鍵は存在とJSONの形式だけを調べ、秘密鍵の値は出力しません。

`--no-sync`は、この確認中にライブラリを追加しないための指定です。必要なものが不足して実行できない場合は、追加する内容を説明してもう一度許可を得ます。

診断後は、次のような短い形で利用者へ現在地を伝えます。

```text
確認できたこと
- プログラムの読み込み：完了
- Googleの鍵：未設定
- GA4への接続：未確認

次はGoogleの鍵を作ります。Google Cloudの画面を開いてください。
```

診断結果に実際のサイト名やIDが含まれる場合は、利用者へ伝える必要があるものだけを抜き出します。JSON全体は貼り付けません。

## 3. 次に必要な作業だけを案内する

| 診断結果 | AIが行うこと | 利用者へ頼むこと |
|---|---|---|
| 作業フォルダが違う | README.mdがある場所を特定する | AIツールでそのフォルダ全体を開く |
| `uv`がない | OSに合う導入方法を示す | インストール後にAIツールを開き直す |
| サンプルを読めない | エラーと対象ファイルを確認して直す | 権限変更など本人の操作が必要な場合だけ頼む |
| Googleの鍵がない | 鍵を置くフォルダを作る | Google CloudでサービスアカウントとJSON鍵を作る |
| 鍵のJSONが不正 | パスとファイル形式を確認する | 正しいJSON鍵を指定の場所へ置く |
| GA4が見えない | APIと権限のどちらで止まったか確認する | 該当するGoogle管理画面の設定だけを直す |
| GA4が複数見える | 候補の表示名とIDを整理する | 分析するプロパティを選ぶ |
| 保存済み情報がある | 内容を読み、済んだ質問を飛ばす | 不足している情報だけ答える |
| GA4接続済み | GTM・Search Console・BigQueryの追加効果を説明する | 今回一緒に設定するものを決める |

Google側の画面操作は[GA4の初回セットアップ](./setup-ga4.md)に沿って案内します。文書を丸ごと利用者へ渡して「全部終えてください」とは言わず、現在地の次に必要な節だけを使います。

## 4. Googleの鍵を確認する

鍵が未設定なら、[GA4の初回セットアップ](./setup-ga4.md)の手順1〜3を順番に案内します。

1. AIが鍵の保存先フォルダを作る
2. 利用者がGoogle CloudでサービスアカウントとJSON鍵を作る
3. 利用者がダウンロードした鍵を指定の場所へ移す
4. AIが`tools/setup_status.py`を再実行し、形式とサービスアカウントのメールアドレスを確認する

サービスアカウントのメールアドレスは権限追加に必要なので表示してかまいません。`private_key`など、それ以外の鍵の中身は表示しません。

## 5. GA4の権限と接続を確認する

鍵を確認できたら、AIが閲覧可能なGA4アカウントを調べます。

```bash
uv run --no-sync --project 02_basic_measurement/measurement_design python 02_basic_measurement/measurement_design/scripts/list_properties.py
```

- 0件なら、[GA4セットアップの手順4](./setup-ga4.md#4-ga4プロパティに閲覧権限を与える)を案内します
- APIが無効なら、[手順5](./setup-ga4.md#5-google-analyticsの機能をgcp側で有効にする)を案内します
- 複数候補がある場合は、表示名とIDを利用者に示して対象を確認します

対象を確認できたら、AIが管理用APIと分析用APIの両方へ接続できるか再確認します。`123456789`は確認済みのIDに置き換えます。

```bash
uv run --no-sync --project 02_basic_measurement/measurement_design python 02_basic_measurement/measurement_design/scripts/run_phase.py --property-id 123456789 --client setup-check preflight
```

出力されたプロパティ名とIDを利用者へ示し、対象サイトと一致するか確認します。一致の返答を得るまで保存しません。

## 6. サイトの情報を保存する

GA4プロパティを確認したら、保存済みのサイト情報をもう一度読みます。未登録なら、最初に対象サイトURLを確認します。AIはURLのトップページとGA4プロパティ表示名からサイト表示名を読み取り、ドメインまたはブランド名から保存用の英数字識別名を作ります。サイト名と識別名を白紙の質問として並べず、候補が曖昧・矛盾・重複する場合だけ利用者へ確認します。

計測チェックを続けるため、次の不足情報を一度に確認します。

- 対象サイトURL
- 問い合わせ完了や購入など、成果として見るものと対応するGA4イベント名
- 希望するレポート形式。希望がなければMarkdownのみ

回答後、確認済みのGA4プロパティIDとあわせて、`01_context_management/src/context_store/writeback.py`の`ensure_client_registered()`、`save_business_profile(site_url=...)`、`save_measurement_ids()`、`save_kpi_info()`、`save_output_format_preference()`を使って保存します。既にある値は聞き直したり、空の値で上書きしたりしません。

## 7. GTM・Search Console・BigQueryを選ぶ

GA4の接続後、次の説明をして希望を確認します。

```text
GA4への接続は完了しました。
GTMをつなぐと、タグ・トリガー・変数の設定をGA4の実データと照合できます。
Search Consoleをつなぐと検索語・表示回数・掲載順位を確認できます。
BigQueryをつなぐと、成果に至るまでのページ遷移を確認できます。
3つとも任意です。今回一緒に設定するものはありますか？ 不要なら「今回は不要」と答えてください。
```

Search ConsoleまたはBigQueryを設定する場合は、共通で使う基本分析用の環境を先に確認します。未準備なら必要なライブラリの内容を説明し、許可済みの範囲を確認して `uv sync --locked --project 04_traffic_analysis/parameter_management` を実行します。追加の許可が必要なのは未承認のインストールだけです。BigQueryだけ設定する場合もこの準備を行います。

### GTM

設定する場合は、保存済みのGTMアカウントID・コンテナIDと接続状態を先に確認します。未保存なら対象のGTMアカウントID・コンテナIDを利用者に確認し、[GA4セットアップの手順8](./setup-ga4.md#8-任意gtmの権限とapi有効化)に沿って、同じサービスアカウントへの読み取り権限とTag Manager APIの有効化を案内します。接続を確認できたIDは`save_measurement_ids()`で保存します。利用者がGTMを使っていない、または今回は設定しない場合は、未設定のまま進めます。

### Search Console

設定する場合も、まず保存済みのプロパティと実際に使われる鍵を診断結果で確認します。`SC_SA_KEY_PATH`が未設定ならGA4と同じサービスアカウントを使います。別鍵が設定されている場合は、そのサービスアカウントを使い続けるかを利用者に確認し、勝手にGA4用へ戻しません。

サイトURLが分かっていれば、権限追加を案内する前にAIが接続を確認します。

```bash
uv run --no-sync --project 04_traffic_analysis/parameter_management python 04_traffic_analysis/parameter_management/scripts/fetch_search_console.py --match-site-url https://example.com/
```

候補を利用者が確認したら、`save_measurement_ids()`で保存します。既に保存済みの候補へ接続できた場合は、設定済みとして権限追加を飛ばします。候補がない場合にだけ、[GA4セットアップの手順6-1](./setup-ga4.md#6-1-search-console)を使い、診断結果に表示されたサービスアカウントのユーザー追加とAPI有効化を案内します。GA4の完了状態は取り消しません。

### BigQuery

設定する場合も、まず保存済みの出力先と実際に使われる鍵を診断結果で確認します。`BQ_SA_KEY_PATH`が未設定ならGA4と同じサービスアカウントを使います。別鍵が設定されている場合は、そのサービスアカウントを使い続けるかを利用者に確認します。

保存済みの出力先がなければ、GA4の「BigQueryのリンク」に表示されるプロジェクトとデータセットを利用者に確認してもらいます。出力先が分かったら、権限追加を案内する前にAIが接続を確認します。

AIはデータセットとGA4日次テーブルの存在を確認し、最新日次テーブルを参照するdry runで読み取り権限・必要な列・ジョブ作成権限を確認します。実データは取得しません。期間全体の充足とデータの品質は分析時に別途確認します。

```bash
uv run --no-sync --project 04_traffic_analysis/parameter_management python 04_traffic_analysis/parameter_management/scripts/check_bigquery_access.py --project-id PROJECT_ID --dataset DATASET
```

確認が成功したら、プロジェクトIDとデータセットをサイト情報へ保存します。権限不足の場合は、[GA4セットアップの手順6-2](./setup-ga4.md#6-2-bigquery)に沿って必要な権限だけを案内します。`no_ga4_tables` の場合は出力先・エクスポート状況を確認し、「データセットには接続できたが分析準備は未完了」と伝えます。日次出力が未作成なら権限追加を繰り返さずに進めます。

## 8. 完了を伝える

最後にローカル診断を再実行し、GA4と、利用者が選んだ任意接続を再確認します。完了報告は次の形にします。

```text
セットアップが完了しました。
- プログラムの読み込み：完了
- GA4：接続済み（プロパティ名・ID）
- GTM：接続済み／今回は設定しない
- Search Console：接続済み／今回は設定しない
- BigQuery：接続済み／今回は設定しない
- サイト情報：保存済み

次に何をしますか？
- 計測チェック
- 市場・顧客理解
- 基本分析
- サイト改善案の作成

基本分析やサイト改善まで進める場合は、先に顧客と競合の前提を整理してから数字を読み、その結果を改善案へつなぐ「市場・顧客理解 → 基本分析 → サイト改善案」の順がおすすめです。未実施の工程があれば、そこから続けられます。
```

セットアップだけを頼まれた場合は、分析を自動開始せず、上のように次に行うことを質問して返答を待ちます。基本分析またはサイト改善案を希望されたときは、既存成果物を確認し、未実施なら「市場・顧客理解 → 基本分析 → サイト改善案」の順を案内します。利用者が基本分析だけなど軽い進め方を明示した場合は、その希望を優先します。計測チェックも依頼されている場合、または利用者が計測チェックを選んだ場合は、計測チェックの正本へ進みます。
