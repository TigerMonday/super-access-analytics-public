# GA4を読めるようにする（初回セットアップ）

このスーパーアクセス解析を、サイトで使用中のGA4に接続します。

[READMEの準備](../README.md)を終え、AIツールでこのフォルダを開いてから進めてください。フォルダの作成と最後の接続確認はAIに頼めます。

AIに「セットアップしたい」と伝えて進めている場合は、この文書を最初から一人で読み進める必要はありません。AIが現在の設定を確認し、次に必要な操作だけを順番に案内します。操作が終わったら、同じチャットで「できました」と伝えてください。

接続には、プログラム用のGoogleアカウント（**サービスアカウント**）と、**Googleの鍵**が必要です。Googleの鍵は、このスーパーアクセス解析がGA4を読んでよいことをGoogleへ示すJSONファイルです。パスワードに近いものなので、他人に渡したりチャットへ添付したりせず、指定のフォルダに保存します。

まずは手順1〜5と動作確認を終えれば、GA4を使えます。GTM、Search Console、BigQueryは任意ですが、同じタイミングで権限を追加すると確認・分析できる内容が増えます。

## 事前に確認しておくこと

- **GA4の管理者権限が必要です。** [手順4（GA4プロパティに閲覧権限を与える）](#4-ga4プロパティに閲覧権限を与える)のユーザー追加は「編集者」ではできません。管理者でない場合は、この文書を渡して依頼してください。
- **会社のGoogle Workspaceを使っている場合、組織のポリシーでGCPプロジェクトを新規作成できないことがあります。** 心当たりがあれば、[手順1（GCPプロジェクトを作る）](#1-gcpプロジェクトを作る)を始める前に、[補足](#補足)内の[「誰が作業するか」](#誰が作業するか)を確認してください。

## 全体の流れ

1. Google Cloudのプロジェクトを用意する（この文書ではGCPプロジェクトと呼びます）
2. サービスアカウントと鍵ファイルを作る
3. 鍵ファイルをパソコンの決まった場所に置く
4. サービスアカウントに、対象サイトのGA4を読む権限を与える
5. Google Cloudで、データ取得に使う機能を有効にする
6. 必要なら、同じサービスアカウントにSearch Console・BigQueryの権限も追加する
7. [動作確認](#7-動作確認)で、対象サイトに接続できるか確かめる

任意の追加設定は、接続を確認してからでかまいません。

- タグの設定も点検したい → [手順8（GTMの権限とAPI有効化）](#8-任意gtmの権限とapi有効化)

## 1. GCPプロジェクトを作る

1. ブラウザで [Google Cloud Console](https://console.cloud.google.com/) を開きます。Googleアカウントでのログインを求められたら、GA4の管理権限を持つアカウントでログインしてください。
2. 画面上部、ロゴの右側にあるプロジェクト選択のプルダウンをクリックします（初回は「プロジェクトを選択」と表示されています）。
3. 開いたダイアログの右上「新しいプロジェクト」をクリックします。
4. プロジェクト名を入力します（例: `saa-analytics`。あとから見て分かる名前ならなんでもかまいません）。会社のアカウントで組織・場所の指定が分からない場合は、社内のGoogle Cloud管理者に確認してください。
5. 「作成」をクリックします。数十秒で作成が終わり、通知から新しいプロジェクトに切り替えられます。まだ切り替わっていない場合は、上の2で開いたプロジェクト選択のプルダウンから、今作ったプロジェクトを選び直してください。

以降は、このプロジェクトを選んで操作します。画面上部のプロジェクト名を確認してください。

## 2. サービスアカウントを作り、鍵ファイルを取得する

1. 画面左上のメニュー（三本線のアイコン）から「IAMと管理」→「サービスアカウント」を開きます。検索バーに「サービスアカウント」と入力して探してもかまいません。
2. 上部の「＋ サービスアカウントを作成」をクリックします。
3. サービスアカウント名を入力します（例: `saa-ga4-reader`）。IDは自動で入力されます。「作成して続行」をクリックします。
4. 「このサービスアカウントにプロジェクトへのアクセス権を付与する」は何も選ばず、「続行」→「完了」をクリックします。権限は後でGA4側に追加します。
5. 作成したサービスアカウントが一覧に表示されるので、そのメールアドレス（`xxxxx@プロジェクトID.iam.gserviceaccount.com` の形式）をクリックして詳細画面を開きます。このメールアドレスは[手順4（GA4プロパティに閲覧権限を与える）](#4-ga4プロパティに閲覧権限を与える)で使うので、あとで参照できるようにしておいてください。
6. 上部タブの「キー」を開き、「鍵を追加」→「新しい鍵を作成」をクリックします。
7. 鍵の形式は「JSON」を選んだまま「作成」をクリックします。JSONファイルが自動でパソコンにダウンロードされます（ファイル名は `プロジェクトID-ランダムな文字列.json` のような形です）。

このJSONファイルが「サービスアカウント鍵」「SA鍵」です。持っている人はそのアカウントの権限でデータを読めるため、パスワードと同じように管理してください。

### 鍵ファイルの取り扱いで守ること

- **他人に渡したり、チャットやメールに添付したりしないでください。**
- **このツールのフォルダ内に保存しないでください。** 誤って公開しないよう、[手順3（鍵ファイルを置く）](#3-鍵ファイルを置く)で指定するホームフォルダ内に保存します。
- 不要になったら、ファイルを消すだけでなく、GCPコンソールの「キー」タブでも鍵を無効化・削除してください。

## 3. 鍵ファイルを置く

鍵ファイル（ダウンロードしたJSON）を、次の場所に置きます。すでに同じ名前の鍵がある場合は上書きせず、どのサイト用の鍵か確認してください。会社で鍵の管理方法が決まっている場合は、[サービスアカウントの接続・運用](./service-account-operations.md)に沿って用意します。

```
~/.saa/credentials/google-analytics/sa-key.json
```

`~` はホームフォルダのことです。Windowsでいうユーザーフォルダ（`C:\Users\自分のユーザー名`）、Macなら `/Users/自分のユーザー名` を指します。<!-- leak-ok: プレースホルダで実在の環境パスではない -->

### 3-1. `.saa/credentials/google-analytics` フォルダを作る

まず、AIに「GA4の鍵を置くために、ホームフォルダの `.saa/credentials/google-analytics` フォルダを作ってください」と頼めます。自分で作る場合は、次のコマンドを使います。

**Windows**: スタートメニューで「PowerShell」と検索して開き、次の1行を貼り付けてEnterを押してください。

```powershell
New-Item -ItemType Directory -Force -Path ~\.saa\credentials\google-analytics | Out-Null
```

**Mac**: `Command + Space` で検索を開き「ターミナル」と入力して起動し、次の1行を貼り付けてEnterを押してください。

```
mkdir -p ~/.saa/credentials/google-analytics
```

あとでこのフォルダをファイラーから開きたいときは、Windowsならエクスプローラーのアドレス欄に `%USERPROFILE%\.saa\credentials\google-analytics` と入力します。Macならメニューバーの「移動」→「フォルダへ移動」を選び、`~/.saa/credentials/google-analytics` と入力すれば直接開けます。

### 3-2. 鍵ファイルを移動し、名前を変える

1. ダウンロードフォルダにある鍵ファイル（`プロジェクトID-ランダムな文字列.json` のような名前）を、[手順3-1（`.saa/credentials/google-analytics` フォルダを作る）](#3-1-saacredentialsgoogle-analytics-フォルダを作る)で作ったフォルダに移動します。
2. ファイルを右クリックして「名前の変更」を選び、`sa-key.json` に変えます。

Windowsは既定で拡張子（`.json` の部分）を隠します。**画面に `.json` が見えていなければ、`.json` を付けずに `sa-key` とだけ入力してください。** 見えていないのに `sa-key.json` と入力すると、実体が `sa-key.json.json` になってツールが見つけられなくなります。

### 3-3. 正しく置けたか確認する

ファイル名と保存先が正しいか、次のコマンドで確認します。

**Windows** (PowerShell):

```powershell
Test-Path ~\.saa\credentials\google-analytics\sa-key.json
```

`True` と表示されれば置けています。`False` の場合は、実体の名前が `sa-key.json.json` や `sa-key.json.txt` になっていないか確認してください（[手順3-2（鍵ファイルを移動し、名前を変える）](#3-2-鍵ファイルを移動し名前を変える)を参照）。

**Mac** (ターミナル):

```
ls -la ~/.saa/credentials/google-analytics/sa-key.json
```

ファイルのサイズ・更新日時が表示されれば置けています。`No such file or directory` と表示された場合は、名前や場所を確認してください。

Windowsでの実際のフルパスは次の形になります（`{あなたのユーザー名}` は実際のログイン名に置き換わります）。

`C:\Users\{あなたのユーザー名}\.saa\credentials\google-analytics\sa-key.json`<!-- leak-ok: プレースホルダのユーザー名で実在の環境パスではない -->

この場所に置けば、追加の設定は不要です。

### （任意・上級者向け）別の場所に置きたい場合

複数のサイトでそれぞれ別のGA4アカウント・別の鍵を使う場合など、鍵ファイルを既定のパス以外に置きたいときは、環境変数 `GA4_SA_KEY_PATH` にそのファイルの絶対パスを設定すれば、既定のパスの代わりにそちらを見に行きます。環境変数の設定方法はOSやシェルによって異なるため、この文書では扱いません。通常の1サイトの運用ではここまでの手順で足りるので、迷ったら既定のパスにそのまま置くことをおすすめします（1clone＝1サイトの運用については [README.md](../README.md) を参照）。

## 4. GA4プロパティに閲覧権限を与える

1. [Google Analytics](https://analytics.google.com/) を開き、対象のプロパティを選びます。
2. 左下の「管理」（歯車アイコン）をクリックします。
3. 「プロパティ」列の「プロパティのアクセス管理」をクリックします。
4. 右上の「＋」→「ユーザーを追加」をクリックします。
5. メールアドレスの欄に、[手順2（サービスアカウントを作り、鍵ファイルを取得する）](#2-サービスアカウントを作り鍵ファイルを取得する)で控えたサービスアカウントのメールアドレス（`...iam.gserviceaccount.com` で終わるもの）を入力します。
6. 役割は「閲覧者」を選びます（このツールはデータを読むだけで、GA4の設定は変更しません。編集者以上の権限は不要です）。
7. 「追加」をクリックします。

複数のプロパティ（例: Webサイトとアプリを別プロパティで計測している）を分析したい場合は、対象プロパティごとにこの手順を繰り返してください。

## 5. Google Analyticsの機能をGCP側で有効にする

GA4のAPI（ツールがデータを取得する機能）を有効にします。

1. GCPコンソールで、[手順1（GCPプロジェクトを作る）](#1-gcpプロジェクトを作る)で作ったプロジェクトを選んだ状態のまま、検索バーに「Google Analytics Data API」と入力して開きます。
2. 「有効にする」をクリックします。
3. 同じ手順で「Google Analytics Admin API」も検索して有効にします。

Data APIはアクセス数などの取得に、Admin APIはGA4の設定の点検に使います。初回は両方を有効にしてください。

GA4だけを使う場合は、[手順7（動作確認）](#7-動作確認)へ進んでください。Search ConsoleやBigQueryも使う場合は、続けて手順6へ進みます。

## 6. （任意）Search Console・BigQueryの権限も追加する

どちらもGA4の接続に必須ではありません。ここで一緒に設定しても、必要になってから追加してもかまいません。

| 追加する接続 | 分析できること |
|---|---|
| Search Console | Google検索で使われた検索語、表示回数、クリック数、掲載順位 |
| BigQuery | 成果が起きるまでに同じセッション内で閲覧されたページの順序 |

### 6-1. Search Console

GA4用に作った同じサービスアカウントと鍵ファイルを使えます。鍵を新しく作る必要はありません。

1. [Google Search Console](https://search.google.com/search-console/)で対象サイトを開きます。
2. 「設定」→「ユーザーと権限」→「ユーザーを追加」を開きます。
3. 手順2で作ったサービスアカウントのメールアドレスを入力し、権限を「制限付き」にします。
4. Google Cloud Consoleで、手順1で作ったプロジェクトを選びます。
5. 「Search Console API」を検索して「有効にする」を押します。

対象サイトの所有者権限がない場合は、Search Consoleの管理者へユーザー追加を依頼してください。詳しい確認方法は[Search Consoleの設定](./setup-search-console.md)にあります。

### 6-2. BigQuery

この設定は、GA4からBigQueryへのデータ出力がすでに設定されているサイトだけが対象です。出力を有効にする前のデータはさかのぼって追加されません。設定の有無が分からない場合は、GA4またはGoogle Cloudの管理者へ確認してください。

1. GA4の「管理」→「BigQueryのリンク」を開き、出力先のプロジェクトIDとデータセットを確認します。
2. 出力先プロジェクトのGoogle Cloud Consoleで「IAMと管理」→「IAM」→「アクセス権を付与」を開きます。
3. 手順2で作ったサービスアカウントのメールアドレスを入力します。
4. 次の2つの役割を追加します。
   - `BigQuery データ閲覧者`（`roles/bigquery.dataViewer`）
   - `BigQuery ジョブユーザー`（`roles/bigquery.jobUser`）

BigQueryの出力先は、鍵を作ったプロジェクトとは別になっていることがあります。権限は、GA4の「BigQueryのリンク」に表示された出力先プロジェクトで追加してください。

会社の運用でBigQueryだけ別のサービスアカウントを使う場合は、環境変数`BQ_SA_KEY_PATH`にその鍵ファイルの場所を指定します。指定しなければ、GA4用の鍵を使います。

## 7. 動作確認

### GA4プロパティIDを控える

GA4で対象サイトを選び、「管理」からプロパティの設定を開いて、**数字だけのプロパティID**を控えます。`G-` で始まる測定IDとは別の番号です。見つからないときは [Google公式のプロパティID確認方法](https://developers.google.com/analytics/devguides/reporting/data/v1/property-id)を参照してください。

### AIに接続確認を頼む

このフォルダを開いているAIに、次のように伝えます。URLと番号は自分のものに置き換えてください。

> GA4の鍵の配置、閲覧権限の追加、2つのAPIの有効化が終わりました。対象サイトURLは「https://example.com/」、GA4プロパティIDは「数字のID」です。GA4用の鍵でこのプロパティに接続できるか確認してください。鍵の中身はチャットに表示しないでください。

AIから返された**プロパティ名とIDの両方**が、対象サイトと一致しているか確かめます。

一致していれば接続は完了です。同じAIのチャットで、続けて次の文章を送ってください。

```text
自社サイトのGA4の計測設定をチェックしてください。初めてなので、必要な情報を聞きながら進めてください。レポートはブラウザで読めるHTMLでも出してください。
```

AIが案内するHTMLファイルをブラウザで開き、計測チェックのレポートが読めれば初回の利用は完了です。その後の分析は[READMEの「続けて分析するとき」](../README.md#続けて分析するとき)を参照してください。

### 自分でコマンドを実行する場合

AIに確認を頼んだ場合、この操作は不要です。自分で行う場合は、README.mdがあるフォルダをターミナルで開いて、次の2行を順に実行します。`123456789` は自分のGA4プロパティIDに置き換えてください。`setup-check` は接続確認用の英数字の識別名です。そのままでかまいません。

```bash
cd 02_basic_measurement/measurement_design/scripts
uv run python run_phase.py --property-id 123456789 --client setup-check preflight
```

接続できると、次のように表示されます。

```text
[OK] 対象プロパティ発見: 《プロパティの表示名》 (properties/123456789)
```

表示された名前とIDの両方を確かめてください。計測の正しさは、この後の計測チェックで調べます。

エラーになった場合は、[うまくいかないときの見分け方](#うまくいかないときの見分け方)で原因を確認します。AIに「接続確認がこのエラーで止まったので、原因を調べてください」と頼んでもかまいません。鍵ファイル自体は添付しないでください。

成果物をGoogleドキュメント・スプレッドシートにも書き出したい場合は、[Google出力の設定](./setup-google-output.md)を参照してください（任意）。

## 8. （任意）GTMの権限とAPI有効化

GTM（Google Tag Manager）も接続すると、タグ・トリガー・変数の設定をGA4の実データと照合できます。未接続でもGA4の点検はでき、GTMの項目は「追加取得が必要な項目」として表示されます。

接続には、次の**権限追加とAPI有効化の両方**が必要です。[手順8-1（GTM側でサービスアカウントに権限を与える）](#8-1-gtm側でサービスアカウントに権限を与える)と[手順8-2（GCP側でTag Manager APIを有効にする）](#8-2-gcp側でtag-manager-apiを有効にする)を終えたら、AIに「GTMの設定も終えたので、対象コンテナを読めるか確認してください」と頼みます。接続できない場合は[「うまくいかないときの見分け方」](#うまくいかないときの見分け方)を参照してください。

<a id="8-1-gtm側でサービスアカウントに権限を与える"></a>

### 8-1. GTM側でサービスアカウントに権限を与える

1. [Google Tag Manager](https://tagmanager.google.com/) を開き、対象のコンテナを含むアカウントを選びます。
2. 「管理」→「ユーザー管理」を開きます。
3. 「＋」→「ユーザーを追加」をクリックします。
4. サービスアカウントのメールアドレスを入力し、アカウント権限は「読み取り」、コンテナ権限も「読み取り」を選びます。
5. 「招待」をクリックします。

<a id="8-2-gcp側でtag-manager-apiを有効にする"></a>

### 8-2. GCP側でTag Manager APIを有効にする

[手順5（Google Analyticsの機能をGCP側で有効にする）](#5-google-analyticsの機能をgcp側で有効にする)と同じ要領で、Tag Manager APIを有効にします。

1. GCPコンソールで、[手順1（GCPプロジェクトを作る）](#1-gcpプロジェクトを作る)で作ったプロジェクトを選んだ状態のまま、検索バーに「Tag Manager API」と入力して開きます。
2. 「有効にする」をクリックします。

有効化した直後に接続できない場合は、数分待って再試行してください。APIが無効というエラーが続く場合は、鍵を作ったプロジェクトで有効にしたか確認します。

## うまくいかないときの見分け方

| 症状 | 原因 | 対処 |
|---|---|---|
| `FileNotFoundError: サービスアカウント鍵が見つかりません` | [手順3（鍵ファイルを置く）](#3-鍵ファイルを置く)で指定した場所と違う場所に置かれている | ファイルのパスの綴りと名前（`sa-key.json`）を確認します。既定と別の場所に置いた場合は、環境変数 `GA4_SA_KEY_PATH` を設定し忘れていないか確認します |
| `PermissionDenied` / `403` | [手順4（GA4プロパティに閲覧権限を与える）](#4-ga4プロパティに閲覧権限を与える)の権限付与が漏れている、またはメールアドレスを打ち間違えている | [手順4（GA4プロパティに閲覧権限を与える）](#4-ga4プロパティに閲覧権限を与える)を開き、サービスアカウントのメールアドレス（`...iam.gserviceaccount.com` で終わるもの）が正しく追加されているか確認します。なければ追加し、数分待って再試行します |
| `API has not been used in project ...`（`Google Analytics Data/Admin API`、`Search Console API` または `Tag Manager API`） | 手順5、手順6-1または手順8-2のAPI有効化が漏れている。あるいは鍵ファイルが別のGCPプロジェクトのもの、または有効化した直後で反映待ちの可能性がある | 該当のAPIが有効になっているか、有効にしたプロジェクトと鍵ファイルのプロジェクトが一致しているかを確認します。有効化した直後なら数分待って再試行します |
| GTMのアカウント・コンテナが0件で返る | [手順8-2（GCP側でTag Manager APIを有効にする）](#8-2-gcp側でtag-manager-apiを有効にする)のAPIは有効だが、[手順8-1（GTM側でサービスアカウントに権限を与える）](#8-1-gtm側でサービスアカウントに権限を与える)の権限付与が漏れている | [手順8-1](#8-1-gtm側でサービスアカウントに権限を与える)を開き、対象のGTMコンテナにサービスアカウントが読み取り権限で追加されているか確認します |
| GTM関連の項目だけ「追加取得が必要な項目」扱いになる | 手順8のGTM設定を行っていない | エラーではありません。GTMまで点検したい場合だけ[手順8](#8-任意gtmの権限とapi有効化)を行います |
| BigQueryのページ遷移で `PermissionDenied` / `403` | [手順6-2](#6-2-bigquery)で確認した出力先プロジェクトに、必要な2つの役割が付与されていない | 出力先プロジェクトで、サービスアカウントに`roles/bigquery.dataViewer`と`roles/bigquery.jobUser`を追加します |
| BigQueryのページ遷移で `FileNotFoundError: BigQuery用のサービスアカウント鍵が見つかりません` | 環境変数 `BQ_SA_KEY_PATH` の指定先が違う（GA4用とBigQuery用でサービスアカウントを分けて運用している場合に出る） | `BQ_SA_KEY_PATH` に設定したパスと実際のファイルの場所が一致しているか確認します。分けて運用する必要がなければ、この環境変数自体を設定しません（GA4用の鍵がそのまま使われます） |
| `SSL_ERROR_SSL` / `CERTIFICATE_VERIFY_FAILED` / `unable to get local issuer certificate` | 鍵や権限とは別の原因（パソコンの通信検査ソフトによるもの） | 下の[「証明書のエラーが出るとき」](#証明書のエラーが出るとき)を参照 |

これでも解決しない場合は、止まった手順とエラーメッセージを控え、AIまたはGA4・Google Cloudの管理者に相談してください。鍵やプロジェクトを作り直す前に、ファイルの場所、権限、APIの設定のどこで止まったかを確認します。

### 証明書のエラーが出るとき

エラーメッセージに `SSL_ERROR_SSL`、`CERTIFICATE_VERIFY_FAILED`、`unable to get local issuer certificate` のいずれかが含まれる場合、鍵の配置や権限は正しくても、パソコンに入っている通信検査ソフト（ウイルス対策ソフトなどで、通信の中身を検査する機能を持つもの）が原因で起きることがあります。こうしたソフトは通信を一度復号して検査するために独自の証明書を割り込ませますが、GA4/GTMへの接続に使っている通信方式はOSの証明書の一覧を見ない作りになっており、割り込んできた証明書を「知らない発行元」として拒否してしまいます。

対処は、環境変数 `GRPC_DEFAULT_SSL_ROOTS_FILE_PATH` に、その通信検査ソフトが使っている証明書ファイルの場所を設定することです。証明書ファイルの場所はソフトによって異なるため一概には言えませんが、例えばNortonの場合は `C:\ProgramData\Norton\Antivirus\wscert.pem` になります。使っているソフトが分からない、あるいは自分のパソコンでは環境変数を変更できない（会社支給のパソコンでよくあります）場合は、情報システム部門に「gRPCという通信方式で使う証明書ファイルの場所を知りたい、環境変数 `GRPC_DEFAULT_SSL_ROOTS_FILE_PATH` に設定したい」と伝えて依頼してください。環境変数そのものの設定方法はOSやシェルによって異なるため、[手順3（鍵ファイルを置く）](#3-鍵ファイルを置く)内の[「（任意・上級者向け）別の場所に置きたい場合」](#任意上級者向け別の場所に置きたい場合)と同様にこの文書では扱いません。

この環境変数1つで、GA4データの取得とGTMのタグ・トリガー確認（計測設計のPhase 3）の両方が直ります。GA4はこの環境変数を見に行く通信方式（gRPC）を使っていますが、GTMはそれとは別の通信方式（httplib2）を使っており、本来はこの環境変数を一切見ない作りです。ツール側で「GRPC_DEFAULT_SSL_ROOTS_FILE_PATHが設定されていたらGTM側の通信にも同じ証明書ファイルを渡す」対応をしているため、利用者は1つ設定するだけで済みます（2つの環境変数を使い分ける必要はありません）。

#### 設定を毎回やり直さずに済ませる

環境変数はターミナルのウィンドウ・タブを閉じると消えます。新しく開き直すたびにまた同じ証明書エラーが出る場合は、次の設定をしておくと、以後は毎回設定し直さずに済みます。

**Windows（PowerShell）**

PowerShellで次の1行を実行します。

```powershell
setx GRPC_DEFAULT_SSL_ROOTS_FILE_PATH "C:\ProgramData\Norton\Antivirus\wscert.pem"
```

パスの部分は実際に使っている証明書ファイルの場所に読み替えてください。`setx` はWindowsのユーザー設定として保存するコマンドで、`$env:` を使った一時的な設定とは別物です。**このコマンドを実行した今のウィンドウには反映されません。** 新しくPowerShellまたはコマンドプロンプトを開き直すと、そちらでは自動的に設定された状態になります。

GA4取得ツールは、環境変数が設定済みなのに証明書ファイルが存在しない場合は接続前に停止します。証明書エラー時に現在のプロセスへ環境変数が渡っていなければ、`setx`後のアプリ／ターミナル再起動が必要なことをエラー内で案内します。

**Mac**

ターミナルで使っているシェルの起動ファイルに1行追記します。多くの場合はzshが既定なので `~/.zshrc` に追記します（`echo $SHELL` の結果が `/bin/bash` ならzshではなくbashなので、`~/.zshrc` の代わりに `~/.bash_profile` に追記してください）。

```
echo 'export GRPC_DEFAULT_SSL_ROOTS_FILE_PATH="/実際の証明書ファイルのパス"' >> ~/.zshrc
```

追記した後は、ターミナルを開き直すか `source ~/.zshrc` を実行すると反映されます。

## 補足

設定の理由や、社内で依頼する相手を確認したいときに参照してください。

### なぜサービスアカウントが必要か

このツールでは、次の理由でサービスアカウントを使います。

- **通常のGoogleアカウントでも、GCPプロジェクトの準備は必要です。** 通常アカウントでの動作確認でも、APIの利用にプロジェクトとその利用権限が必要でした。
- **閲覧権限をGA4側で管理できます。** 対象を追加・削除するたびに、ツール側の設定を変える必要がありません。
- **担当者個人のアカウントに依存しません。** 異動・退職で個人のアカウントが使えなくなっても、接続を維持できます。

### 誰が作業するか

[手順4（GA4プロパティに閲覧権限を与える）](#4-ga4プロパティに閲覧権限を与える)は、対象サイトのGA4管理者が行います。「編集者」権限ではユーザーを追加できません。管理者でない場合は、この文書を渡して依頼してください。

この手順にはGoogle Cloud側の操作も含まれます。GA4の管理者権限と、Google Cloudでプロジェクト・サービスアカウント・鍵を作る権限は別です。操作できない場合はGoogle Cloudの管理者に依頼してください。

会社の設定でプロジェクトの作成が制限されている場合は、社内の情報システム部門やGoogle Cloud管理者に[手順1（GCPプロジェクトを作る）](#1-gcpプロジェクトを作る)を依頼してください。「新しいプロジェクト」を押せない、権限エラーが出る場合も同様です。サービスアカウントや鍵も作れない場合は、[手順2（サービスアカウントを作り、鍵ファイルを取得する）](#2-サービスアカウントを作り鍵ファイルを取得する)も依頼します（[Google公式の鍵作成手順と制限](https://docs.cloud.google.com/iam/docs/keys-create-delete)）。
