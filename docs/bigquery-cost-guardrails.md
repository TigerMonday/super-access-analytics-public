# BigQuery分析の費用確認

BigQueryを使う全分析・アドホッククエリに適用する。ユーザーが分析を依頼したことだけを、高額クエリへの同意とみなさない。

## 実行前

1. 課金先プロジェクト、対象データセット、期間、目的、予定実行回数を確認する。
2. 全クエリをdry runし、読み取り量を見積もる。見積もり不能なら実行を止める。
3. 1クエリの見積もりまたは課金バイト上限が5GiBを超える場合は、金額・上限・目的を提示して明示同意を待つ。5GiBは「高額」の価格定義ではなく、保守的な確認境界。利用者がより低い予算を指定した場合はそちらを優先する。
4. 複数クエリ・再試行は予定回数を含めた合計も確認する。一連の依頼の合計見積もりが5GiBを超える場合も同意を得る。小分けにして確認を回避しない。
5. オンデマンドなら対象リージョンの現行単価×見積もりTiBで概算し、課金バイト上限に対応する金額も示す。単価・課金方式が不明なら金額不明と伝え、実行前に確認する。容量課金はスキャン量だけで金額換算せず、予約・オートスケールの予算を確認する。無料枠・キャッシュヒット・途中キャンセルによる無料化を仮定しない。

## 同意が必要な場合

利用者へ「何を調べるか／対象期間／読み取り量／概算金額と上限／実行回数／期間短縮等の代案」をまとめて示し、実行してよいか確認する。応答がない無人実行では停止し、同意を推定しない。課金先・SQL・パラメータ・期間・上限・予定回数を変えた場合、承認範囲を超える再試行は再確認する。

同意は当該の実行に限定し、以後のクエリに使う包括承認として保存しない。同意内容と対象の見積もりは案件内の非公開記録に保存し、顧客向けレポート本文へ出さない。

## 標準の実行経路

CV経路分析は `04_traffic_analysis/parameter_management/scripts/bq_cv_paths.py` を使う。

- `--estimate-only` で実行せずに見積もりを取得する。
- 5GiB超の上限を指定した実行は、見積もりの `approval_fingerprint` を `--approve-cost` に、実際の同意の記録参照を `--approval-reference` に渡した場合だけ進める。AIがユーザーの同意なしにこれらを埋めてはならない。
- 識別値はSQL、パラメータ、課金先、見積もり量、上限から作る。実行直前にもdry runを行い、変化があれば停止する。
- 同意があっても `maximum_bytes_billed` を必ず設定し、承認した上限を外さない。
- この照合は承認対象の取り違え防止であり、ユーザー本人の認証機構ではない。同意の有無は実行エージェントが会話で確認する。
- 独自SQLも同じ費用確認を行い、標準の `run_query` を経由する。複数実行の合計予算は実行エージェントが管理する。Python外のCLI・コンソールを使って制限を迂回しない。
- 接続診断の `check_bigquery_access.py` はdry runのみであり、実クエリを実行しない。

## 根拠

[Google公式の費用見積もり・上限制御](https://docs.cloud.google.com/bigquery/docs/best-practices-costs)と[BigQuery料金](https://cloud.google.com/bigquery/pricing)を参照する。料金はコードに固定せず実行時に課金条件を確認する。dry runと課金バイト上限は、金額や予約容量の総予算を自動保証するものではない。
