# competitor-qa-research スキル

開始前に `../research-quality-standard.md` を全文読み、調査設計・根拠台帳・成果物へ適用する。

Q&A サイトから対象製品・カテゴリーに関する質問・回答を網羅取得し、
ユーザーの疑問・課題・選定軸・詰まりポイントを構造化する。

## このスキルが守る原則

1. **回答よりも質問本文を一次資料として扱う**。質問は「ユーザーの素のニーズ」、回答は「他ユーザーの解釈」。
2. **ベストアンサーと閲覧数 / 回答数を必ず取る**。共感を集めた質問・回答が優先される。
3. **質問を「疑問の型」で分類する**（選定 / 機能 / 価格 / 比較 / 操作 / 解約）。
4. **回答に混入するステマ / 業者投稿を除外する**（特定製品を過剰に推す回答パターンに注意）。
5. **質問の投稿日を必ず残す**（カテゴリは時代で変わるため、5 年前と現在を同列に扱わない）。

## 入力として最低限聞いておくこと

* 対象製品名（自社）と公式 URL / カテゴリー名
* 競合の確定リスト
* 対象 Q&A サイト（指定があれば）。なければ Yahoo!知恵袋を中心に他は補助
* 何を知りたいか（選定軸 / 操作詰まり / 解約理由 / 比較検討の決め手 等）
* 期間（古い質問を含めるか、直近 1〜2 年に絞るか）

## 調査手順（標準フロー）

### Step 1. 対象 Q&A サイトを確定する

| サイト | 性格 | 主な使いどころ |
|---|---|---|
| **Yahoo!知恵袋** | 国内最大、初心者層多め | 製品比較・選定・初歩的な疑問 |
| **OKWAVE / 教えて!goo** | やや専門寄り、解答質が高め傾向 | 技術的な詰まり・解約手順 |
| **Quora（日本語版 / 英語版）** | 英語圏含む、専門家比率高め | 戦略系・専門カテゴリの深堀り |
| **Reddit r/<subreddit>** | 海外コミュニティ、製品別 subreddit が強い | グローバル製品の海外ユーザー声 |
| **Stack Overflow / Stack Exchange** | エンジニア向け技術 Q&A | 開発者向けツール / API の詰まり |
| **note の有料記事 / Zenn のスクラップ** | 個人の試行錯誤メモ | エンタープライズ製品の導入苦労譚 |

カテゴリー特化サイト（例：マンション関連なら eマンション、車なら みんカラ）があれば追加。
**対象製品 × 主要 1 サイト + 補助 1〜2 サイト** が標準カバレッジ。

### Step 2. 質問を網羅取得する

検索クエリは以下を組み合わせる：

```
<対象製品名>
<対象製品名> <競合製品名>            # 比較系
<対象製品名> 解約 / やめた / 乗り換え   # 撤退系
<対象製品名> 使い方 / できない         # 操作詰まり系
<対象製品名> 評判 / 口コミ            # 評価系
<カテゴリ名> おすすめ                # カテゴリ全体
<カテゴリ名> 選び方                   # 初心者層
```

**取得目標**：1 製品あたり 30〜100 件、合計 200 件超を目処に。

質問本文の原文は非公開の根拠台帳に残す。クライアント向け本文には、意味を損なわない短い抜粋か
忠実な要約だけを載せ、一般個人を特定できる情報は除く。

### Step 3. 質問を「疑問の型」で分類する

```markdown
| 型 | 件数 | 代表例 |
|---|---:|---|
| 選定（A vs B） | 35 | 「<対象製品> と <競合> どっちが安い？」 |
| 機能の有無 | 28 | 「<対象製品> で <機能> ってできますか？」 |
| 価格 / 課金 | 22 | 「<対象製品> の月額って〜」 |
| 操作詰まり | 18 | 「<対象製品> で <操作> がうまくいかない」 |
| 解約 / 撤退 | 12 | 「<対象製品> を解約したい / 乗り換えたい」 |
| 業界・カテゴリ初心者 | 9 | 「<カテゴリ> ってそもそも何ですか？」 |
| その他 | 11 | |
```

**「型ごとに最も多い質問」が施策の打ち手候補** になる。
- 選定型が多い → 比較記事・選び方ガイドが効く
- 操作詰まりが多い → ヘルプコンテンツ / オンボーディング改善
- 解約型が多い → リテンション施策の見直し

### Step 4. ベストアンサーを読み解く

ベストアンサーに **「結論として何が選ばれているか」「どの製品が推されているか」** を取る。
ステマ・業者投稿の臭いがするものは別バケットに分ける（極端な推し、URL リンク多数、回答者の質問履歴が偏っている、等）。

```markdown
| 質問 | ベストアンサーの結論 | 推奨製品 | ステマ疑い |
|---|---|---|:---:|
| <Q本文> | <要約> | <競合> | - |
| <Q本文> | <要約> | <対象製品> | △ |
| ... | | | |
```

### Step 5. 「ユーザーが言語化している選定軸」を抽出する

質問・回答の中で **何度も繰り返される単語**（操作性 / 料金 / サポート / 連携 等）を頻度カウント。
**マーケが打ち出している軸とユーザーの言葉のズレ** が示唆になる。

```markdown
| ユーザーが頻繁に使う言葉 | 出現回数 | 関連質問の型 | マーケ訴求軸との一致 |
|---|---:|---|---|
| 操作が簡単 / 直感的 | 45 | 選定 / 操作詰まり | ◎ 一致 |
| 料金プランが分かりにくい | 38 | 価格 / 選定 | × ギャップ |
| サポートが遅い | 22 | 解約 / 操作詰まり | × ギャップ |
| ... | | | |
```

### Step 6. 質問の時系列を見る

直近 1〜2 年で **急増している質問の型** をチェック。
- AI 機能関連の質問が急増 → 市場がそのテーマに動いている
- 解約系が急増 → 競合に流出している可能性
- 比較質問が急増 → 認知が広がっているか、競合が攻めている

```markdown
| 質問の型 | 2024 | 2025 | 直近12ヶ月 | コメント |
|---|---:|---:|---:|---|
| 選定（vs <競合A>） | 12 | 18 | 26 | 競合 A の攻勢の影響？ |
| AI 機能関連 | 0 | 8 | 22 | 急増 |
| 解約 | 5 | 6 | 14 | 直近で急増、要警戒 |
```

### Step 7. 戦略示唆を書く

集めた質問・型・選定軸から、最低 4〜6 個の打ち手候補を出す：

1. **コンテンツ戦略**：型ごとの量が多い質問に対応する記事を <X> 本作る
2. **ヘルプ / FAQ 改善**：操作詰まりの代表 Top 10 を FAQ ページに
3. **訴求軸の再設計**：ユーザーが使う言葉とマーケコピーのギャップを埋める
4. **解約理由の深掘り**：解約系質問の本文を 3〜5 件抜粋して、リテンション施策の素材に
5. **競合監視ポイント**：直近で増えている競合との比較質問を継続モニタリング

## やってはいけないこと

* **古い質問（5年以上前）を最新トレンドとして扱う**：必ず投稿日を確認
* **回答 1 件で全体傾向を語る**：複数質問・複数サイトで繰り返される言及だけ採用
* **ステマ / 業者投稿を区別せずに集計する**：偏った推奨製品の集計が出ると示唆が壊れる
* **要約で意味を変える**：内部の根拠台帳で原文と照合し、クライアント向けには短い抜粋か忠実な要約を使う
* **「Q&A サイトに質問が多い = 製品の問題」とは限らない**：認知が大きいから質問も多い、というケースもある。母数（製品の認知量）で割って解釈する
