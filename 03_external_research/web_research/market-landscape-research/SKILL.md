# 市場ランドスケープ調査

開始前に `../research-quality-standard.md` と `../research-methodology-basis.md` を全文読み、
調査設計・根拠台帳・成果物へ適用する。

このスキルは3Cを作らない。3Cへ入る前の市場境界と市場事実を作り、
`external-research-coordinator` と `competitor-desk-research` に渡す。

## アウトプット

外部リサーチ統括スキル経由では、テーマフォルダの
`data/child_reports/00_market_landscape.md` に次を出力する。

1. 使った前提と意思決定
2. 市場境界（狭義・広義）
3. 市場の規模・構成・変化
4. 規制・技術・流通等の外部要因
5. 直接競合・代替手段・参入候補
6. 顧客セグメントと未確認事項
7. 方法・出典・限界

## 調査手順

### Phase 0: 意思決定と調査質問を決める

「市場を知りたい」で始めない。調査後に何を決めるかを一文にし、必要な問いへ分解する。

```markdown
| 項目 | 内容 |
|---|---|
| 意思決定 | どの顧客課題・セグメント・提供方法を優先するか |
| 調査質問 | 市場の範囲、需要の大きさと変化、代替手段、参入障壁、主要な不確実性 |
| 対象期間 | 数値の対象期間と、公開情報の取得日 |
```

### Phase 1: 市場境界を定義する

次の5項目を固定する。曖昧な場合は狭義・広義の2案を作り、結論への影響を残す。

| 項目 | 確認すること |
|---|---|
| 顧客課題 | 顧客が何を達成・解決するために対価や時間を払うか |
| 商品・サービス | 同じ課題を解く提供物は何か |
| 対象顧客 | 企業・消費者、業種、規模、利用条件 |
| 地域 | 商圏、提供可能地域、規制や言語の境界 |
| 期間 | 現在値、変化を見る期間、季節性 |

市場名が同じでも定義が違えば数値は比較しない。市場境界の根拠を `evidence-ledger.md` に残す。

### Phase 2: 情報源計画を作る

日本市場は、原則として次の順に探す。

1. e-Stat、所管省庁、規制当局、自治体等の公的統計
2. 法定開示、業界を所管する公的機関の資料
3. 対象、期間、定義、回収・推計方法を開示した業界団体・学術研究
4. 企業のIR・公式情報（その企業自身の数値・方針に限る）
5. 方法と原典を明記した専門メディア・調査会社

検索結果の要約、出典不明の市場規模、同じ調査の転載は採用しない。調査会社の無料要約しか読めず、
母集団や推計方法を確認できない場合は「参考値」または「未確認」に落とす。

### Phase 3: 規模・構成・変化を集める

数値ごとに次を記録する。

| 指標 | 値 | 単位 | 定義 | 対象期間 | 地域 | 母集団 | 推計・収集方法 | 出典 | 信頼度 |
|---|---|---|---|---|---|---|---|---|---|

- 売上、利用者数、事業所数、取引量を混同しない。
- 名目値と実質値、税込と税抜、国内と世界、年度と暦年を揃える。
- 直接の市場規模が無ければ、事業所数×該当率×年間支出など検算可能な式で代替推計し、
  入力値ごとの出典と幅を示す。点推計だけを断定しない。
- 上位・下位の異なる統計を足して一つの市場規模を作らない。
- 市場シェアは分母と各社値の定義が同じと確認できる場合だけ計算する。

### Phase 4: 市場を動かす要因を確認する

規制、技術、流通、人口・企業構成、価格、供給制約について、観測事実と将来仮説を分ける。
「成長しているから参入すべき」と短絡せず、変化が対象顧客の行動と自社の意思決定へどう影響するかを書く。

### Phase 5: 競争構造と候補集合を作る

| 種別 | 定義 | 発見方法 |
|---|---|---|
| 直接競合 | 同じ顧客へ近い提供方法で同じ課題を解く | カテゴリ検索、業界名簿、顧客の比較候補、入札・導入事例 |
| 代替手段 | 別の提供方法で同じ課題を解く | 顧客の現行手段、内製、手作業、隣接カテゴリ |
| 参入候補 | 能力・販路・顧客基盤を転用して参入し得る | 隣接企業の新規事業、提携、採用、投資、規制変更 |

業界の収益性や交渉力が意思決定に関係するときだけFive Forcesを使う。使う場合も、各要因を
公開事実へ結び、強弱を雰囲気で採点しない。候補集合を `competitor-desk-research` に渡し、
比較対象を決める。

### Phase 6: 顧客セグメントを作る

公的統計や業界データの区分から、規模、業種、地域、利用状況など意思決定に関わるセグメントを作る。
年齢や役職など、購買行動の違いを説明しない属性で細分化しない。Web上の顧客の声だけで
セグメントの構成比を推計しない。

### Phase 7: 成果物と申し送り

成果物には、結論より先に「使った前提」を置く。末尾に調査方法、採用・除外件数、使えなかった範囲、
偏り、信頼度を置く。`external-research-coordinator` へ次を渡す。

- 採用した市場境界と不確実性
- 市場の規模・構成・変化を支える `evidence_id`
- 直接競合・代替手段・参入候補のロングリストと選定根拠
- 顧客セグメントと、実利用者調査で確認すべき仮説
- 3Cへ入れてよい観測事実と、まだ入れてはいけない未確認事項

## やってはいけないこと

- 3Cの三つの欄を先に作り、後から都合のよい情報を当てはめる
- 検索件数、SNS投稿数、レビュー件数を市場規模や市場シェアに置き換える
- 自社または競合の「No.1」「成長市場」という表現を第三者事実として使う
- 直接競合だけを見て、内製・手作業・隣接カテゴリ等の代替手段を外す
- 定義・期間・地域の違う統計を比較または合算する
- 数字が無い箇所を、出典の追えない民間推計で埋める
