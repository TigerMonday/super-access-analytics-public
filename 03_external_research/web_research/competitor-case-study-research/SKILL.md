# competitor-case-study-research スキル

開始前に `../research-quality-standard.md` を全文読み、調査設計・根拠台帳・成果物へ適用する。

公式導入事例の網羅取得 → 業種×規模マップでの勝者可視化 → 勝ち筋 / 撤退セグメントの確定。
参考実装：過去案件の `リサーチデータ/<案件ID>_導入事例分析.md`（B2B SaaS 案件で実施）
関連：競合 1 社の単独深掘りは `competitor-company-deep-dive` スキル

## このスキルが守る原則

1. **公式 CASE ページから網羅取得する**。Web 記事の又聞きで済ませない。
2. **規模（人数 / ID 数 / 店舗数）と業種を必ず記録する**。これが無いと比較不能。
3. **対象製品が "勝った事例" の決定要因を 4 パターン程度に類型化する**。「業界で勝った」ではなく「特殊条件で勝った」を見抜く。
4. **競合各社の対象製品領域への "侵食事例" を必ず別出しする**。最大の脅威指標。
5. **業種 × 規模マップを必ず作る**。各セルに defacto standard を 1 社書く。
6. **勝ち筋を 3〜4 つに絞り込む**（多すぎるとどれも実行されない）。
7. **撤退セグメントを必ず明記する**。「全部狙う」は戦略ではない。
8. 競合 1 社あたり「なぜ勝った / なぜ負けた」の構造分析を最低 1 件は深掘りする。

## 入力として最低限聞いておくこと

* 対象製品名・公式 URL・公式事例ページ URL
* 競合の確定リスト（先方公式競合があれば最優先）
* 想定読者と用途（提案資料 / 営業ストーリー / 戦略合意の素材 など）
* 業種・規模の優先カテゴリーがあれば（例：建設・介護・アパレル等）

## 調査手順（標準フロー）

### Step 1. 調査スコープを確定する

| 競合 | 取得目標事例数 |
|---|---:|
| 対象製品（自社） | 公式 CASE 全件（多くて 20〜30 件） |
| 主要直接競合 | 各 10〜20 件（業種をばらしてサンプリング） |
| 部分競合 | 各 5〜10 件 |
| 全体合計の目安 | **50〜80 件超** |

事例の少ない競合は「公式事例 < n 件」と注記する（"取れなかった" を取れたことにしない）。

### Step 2. 対象製品の全事例を分解する

公式 CASE 全件について、以下の表を作る：

```markdown
| 事例 | 規模 | 業種 | 決め手・特徴 |
```

* **規模**は「ID 数 / 従業員数 / 店舗数」のどれか。曖昧なら「101-300名」のようにレンジで。
* **決め手**は事例本文から拾う。マーケ訴求軸を流用しない。
* **特徴的なフレーズ**（例：「LINE の携帯番号紐づけ回避」「2-3 万 ID 実績」）はそのまま引用。
* 出展元 URL を残す。

### Step 3. 対象製品の "真の勝ち筋" を逆算する

事例を眺めて、決め手を 3〜4 パターンに類型化する。
例：

| 勝ち筋 | 該当事例 |
|---|---|
| A. 〜系エコシステム × 販売代理店経由 | 事例 1, 事例 2, ... |
| B. 大規模 IT 化トップダウン × デバイス配布起点 | 事例 3, ... |
| C. 既存業務システムとのバンドル販売 | 事例 4, ... |
| D. 会社間情報統制エンタープライズ | 事例 5, ... |

事例から逆算した "勝ち筋" は、マーケが標榜している訴求軸と一致しないことが多い。
**両者がズレている事実が、提案や戦略合意の核**になる。

### Step 4. 競合各社を 1 社ずつ深掘りする

各競合について：

1. 業種別の主要事例（10〜20 件）を規模付きで表に
2. **対象製品領域への "侵食事例" を別行で強調**（最大の脅威指標。例：「飲食大規模に〜社」「観光大規模に〜社」）
3. その競合の "勝ち筋" を一文で要約（「LINE と同じ操作感」「現場業務管理プラットフォーム化」等）
4. その競合のリスク（規制 / 経営課題 / 撤退領域）も併記
5. **直近 1〜2 年の数値変化（採用社数の倍増・売上成長率・上場・AI機能追加 等）を必ず取る**

特に深掘りしたい競合は別ファイルに分ける（`<案件ID>_<競合名>詳細調査.md` 形式）。

### Step 5. 業種 × 規模マップを作る（このスキルの中核）

縦：業種、横：規模帯。各セルに defacto standard を 1 社書く。
⭐ マークで「圧倒的に強い領域」を可視化する。

```markdown
| 業種 | 〜100名 | 100〜500名 | 500〜2,000名 | 2,000〜10,000名 | 10,000名以上 |
|---|---|---|---|---|---|
| 建設・ゼネコン | <競合> | <競合> ⭐ | <競合> / <競合> | <競合> ⭐ | <競合> ⭐ |
| 多店舗アパレル | ... | ... | ... | ... | ... |
| ... 計 15〜20 業種 ... |
```

**マップを書いた直後に必ず "重要な認識" を書く**。
典型的には「対象製品の独占業種はほぼ存在しない。勝った事例は業界全体で勝ったのではなく
各社固有の特殊条件で勝ったにすぎない」というような認識を、エビデンス付きで提示する。

### Step 6. 「本当に勝てる 3 つのニッチ」を確定する

Step 3 の "勝ち筋" を、エビデンスとなる事例と紐付けて 3 つに絞る。
各ニッチについて：

* **事例（4〜5 件）**
* **本質**（なぜそこで勝てるかの構造）
* **戦略**（その勝ち筋を強化するための施策）

を 200〜300 字程度で書く。

### Step 7. 撤退すべきセグメントを明記する

業種×規模マップから、対象製品が事実上勝てていない領域を抜き出す：

```markdown
| 撤退セグメント | 競合勝者 | 撤退理由 |
```

最低 10〜15 セグメントは挙げる。これを書かないと「全方位戦略」になる。

### Step 8. 競合における 3 つの論点を深掘りする

「同じ業界で勝った事例と負けた事例の差は何か」を、構造分析として 2〜3 個書く。
例：

* 「<対象製品> が <特定業界の大手企業> では勝ったのに、同じ業界の他社で負けるのはなぜか」
  → 軸の違い（例：全社IT化軸 vs 現場業務管理軸）を分解
* 「<競合> が <業種> でこれだけ勝てる構造的理由は何か」
* 「対象製品のブランド / 資本構成が将来的に逆風になり得る論点」

### Step 9. MTG / 提案で握りたい論点を抽出する

集めた事実のうち、先方の認識とズレがあるもの・戦略判断が必要なものを 8〜10 点抽出。
**「業界別の事実認識」「販路と営業導線」「戦略選択」の 3 ブロックに分ける**と読みやすい。

## 競合 1 社を別ファイルで深掘りしたいとき

事例の網羅取得ではなく、**特定の競合 1 社を企業ベースで掘る** 場合は、別スキル
`competitor-company-deep-dive` を使う。本スキルは「業種 × 規模マップによる勝者可視化」に
特化していて、企業単体の数値変化・料金・ターゲット詳細は対象外。

## やってはいけないこと

* **業界全体で勝った扱いをする**（事例が 1 件しかないのに「<業界> で強い」と書く）
* **競合事例の侵食を見落とす**（対象製品の "勝ち業界" に競合の大規模事例があれば必ず明記）
* **マップの空欄を残す**（事例が少ないなら「事例少」と明記。空欄のままにしない）
* **勝ち筋を 6 つも 7 つも書く**（3〜4 つに絞らないと営業に伝わらない）
* **撤退セグメントを書かない**（戦略の半分を放棄しているのと同じ）
* **「将来的に AI で勝てる」のような根拠の無い希望論を勝ち筋に入れる**

## 命名についての注意

`Phase 1` `スイートスポット` `バトルカード` 等のコンサル / AI 風用語は使わない。
「勝ち筋」「撤退セグメント」「狙う場面」「侵食」「勝ちゾーン」など日本語の素直な表現で書く。
