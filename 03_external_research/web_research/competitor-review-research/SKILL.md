# competitor-review-research スキル

開始前に `../research-quality-standard.md` を全文読み、調査設計・根拠台帳・成果物へ適用する。

レビューサイトの多面評価で、競合に対する自社プロダクトの実観測ポジションを定量化する。
参考実装：過去案件の `リサーチデータ/<案件ID>_レビューサイト多面評価分析.md`（B2B SaaS 案件で実施）

## このスキルが守る原則

1. **第三者ソースの観測値を集めることに徹する**。公式マーケ資料・自社申告値だけを根拠にしない。
2. **件数・スコア・機能カバレッジを横並びにする**。「点」ではなく「面」で見る。
3. **ユーザーレビュー文から共通の弱み / 強みを抽出する**。スコアだけでは見えない構造的な評価を拾う。
4. **「マーケが打ち出している軸」と「ユーザーが実感している軸」のギャップを必ず書く**。
5. 数値は必ず取得日付と取得元 URL を残す（後で陳腐化判定するため）。

## 入力として最低限聞いておくこと

* 対象製品名（自社）と公式 URL
* 競合の確定リスト（先方公式競合があれば最優先。Web 上の "競合っぽいもの" を勝手に増やさない）
* 想定読者（クライアント経営層 / マーケ担当 / 提案資料の根拠 など）
* MTG 日付・締切（取得日付の鮮度確保のため）

不明な点があれば質問して埋める。リサーチ範囲を勝手に広げない。

## 調査手順（標準フロー）

### Step 1. レビューサイトの対象を確定する

対象製品のセグメントによってカバーするサイトを切り替える。

#### B2B SaaS / ツール向けの定番

| サイト | 性格 | 取得すべき指標 |
|---|---|---|
| **ITreview** | エンタープライズB2B SaaS最大手 | レビュー件数、総合スコア、Grid 認定（Leader 等）、レビュー本文 |
| **BOXIL SaaS** | スマートキャンプ運営、スコア・ランキング横断 | スコア、業界順位、レビュー件数、レビュー本文 |
| **IT-trend** | 資料請求型 | 資料請求ランキングの圏内 / 圏外 |
| **PRONIアイミツ SaaS** | コンシェルジュ型、機能カバレッジ評価あり | 機能カバレッジ（n機能中の対応数） |
| **起業LOG SaaS** | 中堅起業層 / 多製品比較 | 採用社数・推奨度、レビュー本文 |
| **STRATE / キーマンズネット / ミナオシ** | 補足 | 補足参考 |

カテゴリー別に他に強いサイトがあれば追加（人事系なら HRogマップ、勤怠なら勤怠ナビ、等）。

#### B2C 商品 / 家電 / ガジェット向けの定番

| サイト | 性格 | 取得すべき指標 |
|---|---|---|
| **価格.com** | 国内 B2C ガジェット最大手 | 売れ筋ランキング、製品別レビュー（件数・5段階評価）、本文 |
| **Amazon カスタマーレビュー** | EC 内レビュー、自然な購入者比率高 | 星評価平均、件数、Vine / Top レビュアー比率、本文 |
| **ヨドバシ.com レビュー** | 家電 / ガジェット補完 | 件数、星評価、本文 |
| **mybest / kakaku.com マガジン** | エディトリアル系比較記事 | 比較記事内の順位 / コメント |
| **Google ショッピング / 楽天** | EC ストア横断 | 星評価、件数 |

#### コスメ・美容 / 飲食店・施設 / アプリの定番

| カテゴリ | 主要サイト |
|---|---|
| コスメ・美容 | @cosme / LIPS / アットコスメショッピング |
| 飲食店 / 施設 | 食べログ / Google マップ / Retty / Tabelog 公式 API |
| アプリ / モバイル | App Store / Google Play レビュー |
| 不動産・住宅 | SUUMO / HOMES のクチコミ |
| 自動車 | みんカラ / カーセンサー / Goo-net |

**対象 4〜6 製品 × そのセグメントで強いサイト 5〜7 個** が標準カバレッジ。
セグメントを跨ぐ場合（例：B2B SaaS でも一部は Amazon でも売っている）は両方カバーする。

### Step 2. 横断データを集める（必ず取得日付を残す）

以下 6 観点で必ず数値を取りに行く。空欄なら「取得困難」と明記する（嘘の数値を入れない）。

1. **レビュー件数横断**（最重要・最初の発見になることが多い）
2. **総合スコア横断**（同一サイト内で比較。サイトごとの母数差を念頭に）
3. **業界順位・認定**（BOXIL業界順位、ITreview Grid、外部調査 No.1 等）
4. **市場シェア統計**（日経BPコンサル / BOXIL シェア / 起業LOG 採用社数 等、複数調査を並べる）
5. **機能カバレッジ**（PRONIアイミツ の n 機能中 m 対応など、出ているなら必ず取る）
6. **レビュー本文の共通弱点 / 共通強み**（複数サイトで何度も出てくるものだけ拾う。1 サイト 1 回の指摘は採用しない）

### Step 3. 競合の最新動向を 1 社ずつ書く

「いつ / 何件 / どの認定 / どの AI 機能 / どの業界に侵食」の 5 点で各競合を 200〜400 字程度に要約。
**特に "対象製品が独占していたはずの差別化軸（国産・ISO・AI・大規模実績 等）を取りに来ている競合"
は脅威レベルとして明記する**。

### Step 4. 戦略示唆を必ず書く（5 項目を目安に）

数値の列挙で終わらせない。最低でも以下 5 つの問いに答える：

1. このまま直販 Web マーケに投資する ROI は妥当か（レビュー件数差 / シェア差 / 機能カバレッジ差から）
2. レビュー獲得施策の優先度はどこに置くか（直販投資より先に着手すべきか）
3. 製品改善とマーケの整合性が取れているか（マーケで打ち出している軸が実ユーザーレビューに反映されているか）
4. 訴求軸の再設計は必要か（ユーザーレビューで認知されている軸 vs 認知されていない軸）
5. 急成長競合への対抗策（撤退 / 軸変更 / 正面対抗 のどれか）

### Step 5. MTG で握りたい論点を抽出する

集めた数値のうち「先方の認識とギャップがありそうな数値」を 5〜6 点ピックアップ。
これがそのまま提案 / MTG の議題候補になる。

## やってはいけないこと

* **レビュー本文を 1 件読んで全体傾向のように書く**（最低でも 3 サイト共通 / 5 件以上で言及されているもののみ採用）
* **取得日付・URL を残さない**（半年後に再現できなくなる）
* **競合の「最新動向」を一般論で書く**（具体的な数値・年月・事例名で書く）
* **示唆セクションを「がんばりましょう」レベルで終わらせる**（撤退 / 投資シフト / 訴求変更 のどれかに必ず落とす）
* **クライアントが公式に競合と認めていないツールを勝手に競合扱いする**

## 命名についての注意

`Phase 1` `スイートスポット` `バトルカード` 等のコンサル / AI 風用語は使わない。
日本語の素直な表現（「勝ち筋」「撤退セグメント」「狙う場面」等）で書く。
