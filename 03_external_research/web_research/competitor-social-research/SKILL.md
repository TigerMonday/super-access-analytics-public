# competitor-social-research スキル

開始前に `../research-quality-standard.md` を全文読み、調査設計・根拠台帳・成果物へ適用する。

SNS 上の投稿を取得・分類して、感情・話題・拡散・トレンドの推移を構造化する。

## このスキルが守る原則

1. **取得期間を明示する**（直近 1 週間 / 3 ヶ月 / 1 年 のいずれか）。期間を明示しない SNS 分析は使えない。
2. **ノイズを除去する**：bot 投稿、引用 RT のみ、ハッシュタグ羅列、業者と思われるアカウントは除外。
3. **エンゲージメント（いいね / RT / 返信）を必ず取る**。同じ投稿でも 1 いいね と 1 万いいねでは重みが違う。
4. **原文は非公開の根拠台帳に残す**。クライアント向け本文は短い抜粋か忠実な要約にする。
5. **個人を特定する形での引用は避ける**（公開アカウントでも、文脈を切り取らない）。
6. **「特定の 1 投稿が拡散した」と「継続的に話題がある」を区別する**。バズ単発と恒常トピックは別物。

## 入力として最低限聞いておくこと

* 対象製品名（自社）と公式アカウント（あれば）
* 競合の確定リスト
* 対象 SNS（指定があれば）。なければ X を中心に Reddit / 5ch / note を補助
* 何を知りたいか（感情 / 炎上履歴 / トレンド推移 / SOV / 影響力ある発信者）
* 期間（直近 7 日 / 30 日 / 90 日 / 1 年）

## 調査手順（標準フロー）

### Step 1. 対象 SNS を確定する

| SNS | 性格 | 主な使いどころ | 取得手段 |
|---|---|---|---|
| **X（旧 Twitter）** | リアルタイム性最強、感情拡散 | 炎上監視・トレンド把握・SOV | 検索 UI / X API |
| **Reddit** | 海外コミュニティ、テーマ別 subreddit | グローバル製品のディープな声 | Reddit 検索 / API / pushshift |
| **5ch（旧 2ch）** | 国内匿名コミュニティ、辛口 | ネガティブ評価・本音 | 専用検索（要注意：ノイズ多） |
| **Threads** | Meta 系、ややポジティブ寄り | ブランド系・コンシューマ向け | Threads UI |
| **note** | 個人エッセイ・体験記 | 導入後の長文体験記、撤退理由 | note サイト内検索 |
| **Instagram / TikTok** | ビジュアル中心、若年層 | コスメ・飲食・アパレル・体験型 | サイト内検索 |
| **Threads / Discord / Slack public** | コミュニティ別 | エンジニア向け、ニッチ系の本音 | 公開サーバの検索 |

**対象製品セグメント別の推奨組合せ**：
- B2B SaaS / 開発者ツール：X + note + Reddit + Hacker News + Stack Exchange
- B2C ガジェット / 家電：X + Reddit + YouTube レビュー動画コメント
- コスメ / 美容：X + Instagram + TikTok + LIPS
- 飲食・店舗：X + Instagram + Google マップクチコミ

### Step 2. 取得手段を選ぶ

**X 検索 UI**（推奨）：bot 除外には `-filter:bot`、フィルター付けて検索。
**Browser MCP / Playwright**：UI スクレイピング（規約遵守、過剰アクセス禁止）。
**各 SNS の公式検索 / API**：Reddit・note・Instagram 等は Step 1 の表の「取得手段」列に従う。

**取得目標**：1 製品あたり 50〜200 件のエンゲージメントを持つ投稿、合計 300〜500 件。

### Step 3. 投稿を感情ラベルで分類する

```markdown
| 感情 | 件数 | 割合 | 代表投稿（一部要約） |
|---|---:|---:|---|
| ポジティブ | 120 | 40% | 「<対象製品> 使いやすい」「導入してよかった」系 |
| ニュートラル | 90 | 30% | 「<対象製品> を使い始めた」系（事実報告） |
| ネガティブ | 60 | 20% | 「<対象製品> 動かない」「サポート遅い」系 |
| 比較・選定 | 30 | 10% | 「<対象製品> vs <競合> どっち」 |
```

注意：自動分類は外す可能性が高いので、**サンプリングして 50 件は目視で見る**。

### Step 4. トピック（話題）を抽出する

頻出単語・話題を 5〜10 個のクラスタに分ける：

```markdown
| トピック | 件数 | 主要投稿 | 感情傾向 |
|---|---:|---|---|
| AI 機能 / 自動化 | 85 | <代表投稿引用> | ポジティブ多 |
| 価格 / プラン変更 | 42 | <代表投稿引用> | ネガティブ多 |
| 連携 / 統合 | 38 | <代表投稿引用> | ニュートラル |
| 操作性 / UI | 28 | <代表投稿引用> | 混在 |
| サポート対応 | 22 | <代表投稿引用> | ネガティブ多 |
```

### Step 5. 拡散イベントを特定する

エンゲージメント上位 10〜20 投稿を時系列で並べる。**何が原因でいつバズったか / 炎上したか** を 1 行で要約。

```markdown
| 日付 | 投稿（要約） | エンゲージメント | 起点 |
|---|---|---:|---|
| 2025-08-15 | 「<対象製品> の AI 機能 X が話題」 | 12,000 いいね | 新機能リリース |
| 2025-11-02 | 「<対象製品> 障害発生」 | 8,500 RT | システム障害 |
| 2026-02-10 | 「<対象製品> 料金改定批判」 | 6,200 RT | 価格改定発表 |
```

**過去 1〜2 年の重大イベント** を把握しておくと、現在のトレンドの背景が読める。

### Step 6. SOV / 言及量の時系列

```markdown
| 月 | 自社 | 競合A | 競合B | 競合C | 自社シェア |
|---|---:|---:|---:|---:|---:|
| 2025-12 | 1,200 | 4,800 | 2,200 | 1,800 | 12% |
| 2026-01 | 1,450 | 5,100 | 2,400 | 1,750 | 13% |
| 2026-02 | 1,800 | 5,800 | 3,000 | 1,900 | 14% |
```

自社・競合それぞれの言及数を同一条件（期間・検索クエリ）で数え、月次で並べる。

### Step 7. 影響力ある発信者を評価する

企業・公人・業界KOLは公開上の役割を確認して別建てで管理する。一般個人は匿名化する。
**「誰が」言ったかが「何を」言ったかと同じくらい重要**な領域。

```markdown
| 発信者 | フォロワー数 | 直近言及 | 感情 | 影響評価 |
|---|---:|---|---|---|
| @<業界KOL> | 50K | 「<内容>」 | ポジティブ | 大 |
| @<競合公式> | 30K | 「<内容>」 | ニュートラル | - |
```

### Step 8. 戦略示唆を書く

集めた声・トピック・拡散イベントから 4〜6 個の打ち手：

1. **トピック対応**：ネガティブ多のトピック上位 3 つに対する公式コミュニケーション設計
2. **炎上監視ルール**：影響力ある発信者の言及検知 / 公式アカウントの応答 SLA
3. **施策の SOV 目標**：競合との SOV 差を埋めるための施策設計
4. **新機能の告知設計**：過去のバズ起点から学ぶ「拡散しやすいリリース文」
5. **KOL とのリレーション**：影響力ある発信者リストの整備

## やってはいけないこと

* **bot / 業者投稿を除外せずに集計する**：分布が大きく歪む。bot 除外のフィルタリングを必ず通す
* **1 つのバズ投稿で全体傾向を語る**：そのバズが 1 アカウント由来か、複数発信者由来かを区別
* **個人を特定する形で批判的に引用する**：公開アカウントでも、文脈を切り取らない
* **取得期間を明示せずに数値を出す**：「言及 1,200 件」だけ書くのは無意味、必ず期間付き
* **感情分類を自動 100% に頼る**：必ず 50 件は目視で確認、誤分類を補正
* **SNS の声を「ユーザー全体の意見」として扱う**：SNS で発信するユーザーは偏ったセグメント。母集団の偏りを念頭に
* **規約違反のスクレイピング**：各 SNS の利用規約と robots.txt を遵守、過剰アクセス禁止
