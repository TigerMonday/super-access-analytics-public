# competitor-company-deep-dive スキル

開始前に `../research-quality-standard.md` を全文読み、調査設計・根拠台帳・成果物へ適用する。

特定競合 1 社を企業ベースで深掘りし、対象製品との比較・勝てる条件 / 譲るべき領域を確定する。

## このスキルが守る原則

1. **数値変化を必ず時系列で取る**。「現時点で X 社」ではなく「過去 2〜3 年で X→Y→Z 社に成長」と書く。
2. **料金はユーザー単価まで計算する**。プラン表のスナップショットで終わらせない。
3. **対象製品との比較表を必ず作る**。「強い」「弱い」を相対化しない単独評価で終わらせない。
4. **対象製品が勝てる条件 / 譲るべき領域を明記する**。「全方位で勝てる」とは書かない。
5. 数値・引用は **出典 URL と取得日付** を残す。

## いつ使うか

- `competitor-case-study-research` の業種 × 規模マップで「特に脅威の競合」が浮かび上がったとき
- レビュー / シェア / 機能カバレッジで急成長している競合を見つけたとき（`competitor-review-research` 由来）
- クライアントが特定競合を強く意識しているとき（営業案件で名指しされる、議事録に頻出する）
- 提案資料の「主要競合の脅威分析」章を厚くしたいとき

## 入力として最低限聞いておくこと

* 対象製品名（自社）
* 深掘り対象の競合名 / 公式 URL
* 想定読者と用途（提案資料 / 営業ストーリー / 経営層への報告 など）
* 公開されている範囲（上場有無 / 直近の IR / プレスリリース）

## 調査手順（標準フロー）

### Step 1. 調査動機を明文化する

「なぜ今この競合を深掘りするのか」を最初に書く。例：

- 「直近 1 年で採用社数が X→Y 社に倍増したため、認識を更新する必要がある」
- 「<業界> の大型案件で 3 連敗、勝ちパターンの再確認が必要」
- 「AI 機能追加の発表で訴求が変わった可能性、追従要否を判断する」

動機が無い深掘りは「資料は厚いが意思決定に使えない」状態になる。

### Step 2. 企業情報を確定する

| 項目 | 取得元の例 |
|---|---|
| 設立年 / 創業者 | コーポレートサイト |
| 上場有無 / 上場日 / 市場 | コーポレートサイト / EDINET / 適時開示 |
| 直近売上高 / 営業利益 / 利益率 | 決算説明資料 / 有価証券報告書 |
| 売上成長率（直近 3 年） | 決算資料の時系列 |
| 従業員数 | コーポレートサイト / 採用情報 |
| 資本構成 / 主要株主 | 有価証券報告書 / 適時開示 |
| 直近 1〜2 年の重要イベント | プレスリリース / 適時開示（M&A・業務提携・新機能・上場） |

非上場の場合は売上推計値・採用数・登記情報・業界紙報道で代替。

### Step 3. サービスの数値を時系列で取る

ここが本スキルの中核。**「採用社数」「レビュー件数」「認定」が時系列でどう動いたか** を取りに行く。

```markdown
### 採用社数の年次推移

| 年月 | 採用社数 | 出典 |
|---|---:|---|
| 2023-04 | 1,200 | 公式IR資料 (URL, 取得日) |
| 2024-04 | 2,100 | 公式IR資料 (URL, 取得日) |
| 2025-04 | 3,500 | 公式IR資料 (URL, 取得日) |
| 直近 | 4,200 | プレスリリース (URL, 取得日) |

→ **直近 2 年で約 3.5 倍** の成長。
```

レビューサイト件数（ITreview / BOXIL）、認定（Leader バッジ / シェア No.1 認定）、
受賞歴も同じく時系列で。

### Step 4. 料金プランを単価まで分解する

価格表をそのまま貼るのではなく、**「対象製品との同条件比較が可能な単価」** に分解する。

```markdown
### 料金プラン

| プラン | 月額 | 含まれるユーザー数 | 1ユーザーあたり | 主な機能制限 |
|---|---:|---:|---:|---|
| Lite | 30,000 | 50名まで | 600円 | 基本機能のみ |
| Standard | 80,000 | 200名まで | 400円 | + 〜機能 |
| Enterprise | 要見積もり | 制限なし | （要問合せ） | 全機能 + 専任サポート |

→ 100 名規模なら **400〜600 円 / 月** がレンジ。対象製品は同帯で 500 円なので **同水準**。
```

「同水準」「割安」「割高」を **対象製品との相対** で書く。

### Step 5. ポジショニング・主軸メッセージを言語化する

公式サイトのキャッチコピー、ホワイトペーパー、CEO 発言等から、**競合が打ち出している軸を一文で**。

```markdown
### ポジショニング

> 「<競合キャッチコピー>」
> （公式トップページ, 取得日 YYYY-MM-DD）

実質的な訴求軸：
- 第一軸：<例：現場業務管理プラットフォーム化>
- 第二軸：<例：LINE と同じ操作感>
- 第三軸：<例：エンタープライズ実績>
```

対象製品の訴求軸とどう違うかを次の Step で並べる。

### Step 6. 主要機能のマトリクス

```markdown
| 機能カテゴリ | <競合> | <対象製品> | 差分 |
|---|---|---|---|
| トーク / メッセージ | ◎ | ◎ | 同水準 |
| ファイル共有 | ◎ | ○ | 競合のほうが容量上限大きい |
| AI 機能 | ◎（要約・翻訳・検索） | △（要約のみ） | **競合優位** |
| 外部連携 | ○ | ◎ | 対象製品優位 |
| ... | | | |
```

「◎ ○ △ ×」の判定基準を本文 or 注釈で明記する。

### Step 7. ターゲット業種・規模

`competitor-case-study-research` で取った業種 × 規模マップから該当列を抜粋して、
**「この競合がどの業種 × どの規模で強いか」** を 200〜300 字で要約。

### Step 8. 代表事例の深掘り

事例の中でも「特に脅威」「特に学びがある」 3〜5 件を選び、決め手と数値を本文で書く。
（網羅は `competitor-case-study-research` の仕事なので、ここでは選別したものだけ）

### Step 9. 強みと弱み

**競合の強み**：エビデンス付きで 4〜6 個。
**競合の弱み（対象製品にとっての勝機）**：これも 4〜6 個。

弱みは「規制」「経営課題」「撤退領域」「価格構造」「未対応機能」「サポート体制」等のレイヤーで分けて書くと深くなる。

### Step 10. 対象製品との総合比較表

```markdown
| 観点 | <対象製品> | <競合> | 差 |
|---|---|---|---|
| 採用社数 | X,XXX | Y,YYY | 競合 X 倍 |
| 平均ARPU | XX円/ID/月 | XX円/ID/月 | 同水準 |
| 主要業種 | 〜 | 〜 | 棲み分け or 競合 |
| 強み | 〜 | 〜 | |
| 弱み | 〜 | 〜 | |
| 直近の数値変化 | 〜 | 〜 | |
```

### Step 11. 対象製品が勝てる条件 / 譲るべき領域

**勝てる条件**（3〜5 個）：
- 「<こういう案件なら>対象製品が勝てる」を具体的な条件付きで書く
- 例：「販売代理店経由 × 〜業界 × 100〜300 名規模」

**譲るべき領域**（3〜5 個）：
- 「<こういう案件は>正面対抗しないほうがよい」
- 例：「大規模 IT 化トップダウン × 2,000 名超 × 〜業界」

これが本スキルの最終成果物。

## やってはいけないこと

* **数値のスナップショットで終わる**（時系列を取らないと「成長中なのか減衰中なのか」が分からない）
* **料金表をそのまま貼る**（ユーザー単価まで分解しないと比較できない）
* **強みだけ書いて弱みを書かない**（勝てる条件を出すには弱みが必要）
* **「勝てる条件」を 1 個も書かない**（全方位対抗は戦略ではない）
* **出典 URL と取得日を残さない**（数値が陳腐化したときに再現できなくなる）
