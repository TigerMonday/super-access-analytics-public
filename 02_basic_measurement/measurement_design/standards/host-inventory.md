# 計測ホストの実体調査 — 残す／外すを判定する手順

同一の測定IDが複数のホストに貼られている案件は多い。
**ホスト名とセッション数だけを見て判定してはいけない。**

実際の案件では、当初「意図せず測定IDが貼られた別サイト」と判定しかけた2ドメインが、
実際には**広告費が入っている着地先**だった。測定IDを外していれば、広告の着地が計測不能になっていた。

判定を誤ると次のどちらかが起きる。

| 誤り | 結果 |
|---|---|
| 必要なホストを外す | 広告・記事の成果が計測できなくなる。**気づくのは数ヶ月後** |
| 不要なホストを残す | サイト全体のセッション・コンバージョン率が実態からずれる |

## 手順

### 1. ホスト別のセッションを取得する

`_data/07-data-quality.json` の `hosts`。無ければ `fetch` で取得する。

### 2. 各ホストで「何が計測されているか」を見る

**ここを飛ばさない。** ホスト × ページパスで実際に計測されているページを取得し、
そのURLを開いて中身を確認する。

| 見るもの | 何が分かるか |
|---|---|
| ページパス（上位） | 何のサイトか。記事1本なのか、サービス全体なのか |
| 発火しているイベント | 予約・問い合わせなど成果が発生しているか |
| 参照元 / メディア | 広告が入っているか、オーガニックか |
| ランディングページ | 広告の着地先として使われているか |

### 3. 判定する

| 判定 | 条件 | 対応 |
|---|---|---|
| **本番** | 主サイト | 残す |
| **別サイト（意図的）** | 広告の着地先・別ブランドのオウンドメディアなど、事業として運用されている | **測定IDは残し、レポート側で `hostName` により分離する** |
| **別サイト（意図せず）** | 過去の制作物の残骸・第三者による貼り付け | 測定IDを外す |
| **外部ツール** | スクレイピングツール・監視ツールのアクセス | 除外設定 |
| **正規化漏れ** | `www` あり／なしの重複、ミラー | リダイレクト設定を確認 |
| **未確認** | 実体を見ていない | **判定しない。** `questions.md` へ送る |

**広告費が入っているホストから測定IDを外さない。** 分けて見たいだけなら
`hostName` で絞ればよく、測定IDを外す必要はない。

### 4. 判定できないものはクライアントに聞く

「意図的に同じ測定IDを使っているか」は、こちらでは分からないことがある。
セッション数と実体（何のページか）を添えて確認する。数字だけ見せても判断できない。

## 書き方

調査結果は `docs/domain-inventory.md` にまとめ、計測設計書（`docs/design-doc/`）の
関連する章から参照する。ホストごとに次を書く。

```markdown
## N. `<ホスト名>`（セッション数）— <一言でどういうサイトか>

### 計測されているページ
### 発火しているイベント
### 参照元
### 分かったこと
### 対応
```

**「分かったこと」と「対応」を分ける。** 事実と判断を混ぜると、
後から前提が変わったときにどこを見直せばよいか分からなくなる。
