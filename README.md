# super-access-analytics

「スーパーアクセス解析」は、[株式会社月曜日のトラ](https://tigermonday.com/)が自社サイトのGA4（Google Analytics 4）をAIコーディングエージェントと一緒に分析するために使っているプログラム。<!-- leak-ok: 発行元としての表示（意図的） -->

GA4の数字を分析する前に、計測の設定が正しいかをチェックできる。そのうえで、集客の分析やサイトの改善案づくりをAIに依頼できる。最初にパソコンとGoogle側の設定を済ませれば、その後はAIに日本語で話しかけて使える。

使い方の疑問、不具合、改善要望・感想は、[スーパーアクセス解析のお問い合わせフォーム](https://sdjhe.share.hsforms.com/2YuKJnaAHSpW95m9Hqw5kqA)へお寄せください。

## 何ができるか

| できること | 中身 |
|---|---|
| 計測設計の点検 | GA4・GTMの計測の正確性を、機械34項目・目視19項目の固定一覧で監査する。GTM権限等が不足する項目も未確認として残す。別途、計測設計書を生成できる |
| 基本分析 | GA4を中心に、アクセスや成果の推移、流入元、入口ページなどを比べ、集客の状況を1つのレポートにまとめる。Search Consoleを接続していれば、検索語や掲載順位も確認できる |
| 市場・顧客理解 | Web上の公開情報から市場・競合・顧客・自社を調べ、3C分析、ペルソナ、検討から成果までのカスタマージャーニーを1つのレポートにまとめる |
| CVR改善の施策づくり | 全体方針→対象ページ選定・改善案という2段階で、分析と施策案を作り、それぞれを別の視点でレビューする |
| アドホック分析 | 「この数字はなぜ動いた？」のような単発の問いに、GA4データを取得しながら答える |

必要な機能だけ、AIに日本語で依頼できる。

## 準備するもの

| 項目 | 内容 |
|---|---|
| パソコンとインターネット接続 | 以下はWindows／Mac向けの手順。初回は必要なソフトをダウンロードする |
| Git | このスーパーアクセス解析をパソコンへコピーし、更新するために使う |
| uv | このスーパーアクセス解析に必要なPythonや部品をそろえ、動かすために使う |
| AIコーディングエージェント | パソコン内のファイルを読み、プログラムを実行できるAIツール。Claude Code、Codex、Gemini CLI、GitHub Copilot、Cursorなど、使う製品の案内に従ってインストール・ログインする |
| GA4の管理者権限 | 自分に権限がなければ、[手順4（GA4につなぐ）](#connect-google)を管理者に依頼する |

> [!IMPORTANT]
> このツールはパソコン内でプログラムを実行するため、ブラウザ版のChatGPTやGeminiだけでは動かせない。作成済みのレポートについて相談する用途には使える。認証鍵やGA4の実データは、ブラウザのチャットに添付しないこと。

## 導入手順

**インストール → コピー → AIで開く → GA4につないで計測チェック**の順に進める。インストールとGoogleの設定は利用者が行い、このスーパーアクセス解析の準備・実行はAIに頼む。

### 1. 必要なツールをインストールする

まず、コマンド（操作を指示する文字列）を入力する画面を開く。

- **Windows**：スタートメニューで「PowerShell」を検索して開く。
- **Mac**：`Command + Space`を押し、「ターミナル」を検索して開く。

Gitは、このスーパーアクセス解析をパソコンへコピーするためのツール。uvは、動作に必要なPythonや部品を自動でそろえ、このスーパーアクセス解析を実行するためのツール。

次の2行を1行ずつ貼り付けてEnterを押し、Gitとuvが入っているか確認する。

```text
git --version
uv --version
```

両方のバージョン番号が出れば、[手順2（リポジトリをクローンする）](#clone)へ進む。「見つかりません」「認識されません」「command not found」などが出たツールだけ、次の方法で入れる。

**Windowsの場合**

PowerShellで未導入のツールのコマンドを実行し、画面の案内に従う。

```powershell
winget install --id Git.Git -e --source winget
winget install --id astral-sh.uv -e
```

`winget`自体が見つからない場合は、[GitのWindows向け案内](https://git-scm.com/install/windows)と[uvのインストール案内](https://docs.astral.sh/uv/getting-started/installation/)からインストールする。uvのページではWindows向けの手順を選ぶ。

**Macの場合**

Gitが無ければ、次を実行して表示されたインストール画面に従う。Gitを含むAppleの開発用ツールが入る。

```bash
xcode-select --install
```

uvが無ければ、次を実行する。公式のインストール用スクリプトをダウンロードして動かすコマンド。

```bash
curl -LsSf https://astral.sh/uv/install.sh | sh
```

これらは[GitのMac向け案内](https://git-scm.com/install/mac)と[uvの公式案内](https://docs.astral.sh/uv/getting-started/installation/)に沿った方法。

**インストール後はPowerShell／ターミナルを開き直し、`git --version`と`uv --version`を再実行する。** 両方のバージョン番号が出れば完了。Pythonはuvが用意するので、別途インストールは不要。会社のパソコンでインストールできない場合は、社内の担当者に依頼する。

### 2. リポジトリをクローンする

リポジトリは、プログラムと説明書をまとめたもの。それをパソコンにコピーする操作を「クローン」と呼ぶ。

PowerShell／ターミナルで次の3行を順に実行する。自分のユーザーフォルダにコピーされる。配布元への登録・ログインは不要。

```bash
cd ~
git clone https://github.com/TigerMonday/super-access-analytics-public.git  # leak-ok: 配布元
cd super-access-analytics-public
```

最初の`cd ~`で、自分のユーザーフォルダへ移動してからコピーしている。クローン先は次の場所になる。

- **Windows**：自分のユーザーフォルダ内の`super-access-analytics-public`。エクスプローラーのアドレス欄に`%USERPROFILE%\super-access-analytics-public`と入力すると開ける
- **Mac**：ホームフォルダ内の`super-access-analytics-public`。Finderの「移動」→「フォルダへ移動」で`~/super-access-analytics-public`と入力すると開ける

最後の`cd`で、コピーしたフォルダの中へ移動する。`pwd`と入力すると、実際の保存場所を確認できる。このフォルダを次の手順でAIツールから開く。

すでにクローン済みならコピーし直さず、そのフォルダを使う。「フォルダが既に存在する」というエラーが出たときも、まず以前コピーしたものか確認する。1サイト（1つの会社・ブランド）につき1つのクローンを使う。別のサイトを追加する場合は[複数サイトを見たい場合](#複数サイトを見たい場合)を参照。

#### 更新版が公開された場合

クローン済みのフォルダをClaude CodeやCodexなどで開き、次のように依頼する。

```text
スーパーアクセス解析を最新版に更新してください。
自分で変更したファイルがある場合は、更新前に影響を確認してください。
```

AIは最初に変更中のファイルがないかを確認し、問題がなければ`git pull`でGitHubの最新版を取得する。自分で変更したファイルがある場合は、上書きや競合を避けるため、AIの確認結果を見てから更新方法を決める。作成済みのレポートや認証鍵はGitの更新対象ではない。

自分で更新する場合は、PowerShell／ターミナルでクローン済みのフォルダへ移動し、次を実行する。

```bash
git status
git pull
```

`git status`で変更中のファイルが表示された場合は、`git pull`を実行せず、先にAIへ確認する。

### 3. AIエージェントでフォルダを開く

AIツールを起動し、作業フォルダに`super-access-analytics-public`を選ぶ。**`README.md`だけでなく、フォルダ全体を開く。** ターミナルから起動する製品なら、そのフォルダ内で起動する。

AIのチャット欄に次の文章を送る。

```text
初めて使います。セットアップしたいです。
```

AIが作業フォルダ、必要なツール、付属サンプル、保存済みの設定を確認する。初回は、このスーパーアクセス解析を動かすために必要なPythonや部品をダウンロードする場合がある。AIは、何を入れるか説明して許可を得てからインストールする。完了済みの作業は飛ばし、次に必要な操作だけを案内する。

パソコン内の確認とコマンドの実行はAIが行う。Googleの管理画面など本人にしか操作できないところは、AIの案内に沿って進め、終わったら同じチャットで「できました」と伝える。

<a id="connect-google"></a>

### 4. GA4につなぎ、最初の計測チェックをする

#### 4-1. AIの案内に沿ってGA4につなぐ

GA4からデータを読むために、サービスアカウント（このツール専用のGoogleアカウント）と鍵ファイルを用意する。**Googleの管理画面での設定は、自分または管理者が行う。** GA4の管理者権限に加え、Google Cloudでアカウントや鍵を作れる権限が必要。

AIが現在の設定状況を確認し、[GA4の初回セットアップ](docs/setup-ga4.md)から次に必要な操作だけを案内する。鍵ファイルの意味と扱いも、作成前に説明する。すでに設定済みの項目は繰り返さない。

GTM、Search Console、BigQueryの接続は任意だが、GA4と同じタイミングで権限を追加できる。GTMをつなぐとタグ・トリガー・変数、Search Consoleをつなぐと検索語・表示回数・掲載順位、BigQueryをつなぐと成果に至るページ遷移まで確認できる。GA4接続後、AIが3つを今回一緒に設定するか確認する。

鍵ファイルは手順書で指定するパソコン内の場所に置き、チャットには添付しない。分析データをAIが読むと、利用するAI提供会社へ送信される場合があるため、実データを使う前に[データの取り扱い](docs/data-handling.md)も確認する。

<a id="first-analysis"></a>

#### 4-2. 接続できたら、そのまま計測チェックを頼む

同じAIのチャットで、次の文章を送る。

```text
自社サイトのGA4の計測設定をチェックしてください。初めてなので、必要な情報を聞きながら進めてください。レポートはブラウザで読めるHTMLでも出してください。
```

対象サイトURL、GA4プロパティID（分析対象を指定する数字）、CV（問い合わせ完了・購入などの成果）を聞かれる。サイト名と保存用識別名はURL・サイト・GA4情報からAIが候補を作り、曖昧な場合だけ確認される。分からない項目はAIに確認方法を聞けばよい。回答は保存され、次回から再利用される。

完了したら、AIが案内するHTMLファイルをブラウザで開く。**計測チェックのレポートが読めれば、初回の利用は完了。** GTMなどの権限がないため確認できなかった項目は、レポートに未確認として残る。

## 続けて分析するとき

計測チェックは必要な情報だけで始められる。一通り分析する場合は、次の順でAIに依頼する。済んだ作業は繰り返さなくてよい。

1. **サイトの情報を登録する** — 「自社サイトの事業内容やターゲット、成果の定義を登録したい」。分析に使う前提を整理する。
2. **計測をチェックする** — 「GA4の計測設定をチェックして」。分析の元になるデータが正しく取れているか確認する。
3. **市場・顧客を調べる** — 「市場・競合・顧客を調べて」。数字を解釈するための背景を整理する。
4. **集客と成果を分析する** — 「基本分析をして」。どこから人が来て、何が成果につながっているかを調べる。

その後、改善案を作りたければ「サイトのCVRを改善する施策を考えて」と依頼する。CVRは、訪問に対して成果につながった割合のこと。基本分析やサイト改善まで進める場合は、**市場・顧客理解 → 基本分析 → サイト改善案**の順がおすすめ。セットアップ完了時にも、AIが次に何をするか確認してこの順序を案内する。

## 成果物はどこに出るか

| 何が置かれるか | 置き場所 |
|---|---|
| サイトの前提情報（GA4プロパティID・CVの定義・過去の施策など、登録時に確定して以後聞き直さない情報） | `01_context_management/context/`内のサイト別フォルダ |
| 分析の成果物（レポート・分析ファイル） | `outputs/`内のサイト別フォルダ |

レポートの元になる文章はMarkdown（拡張子が`.md`の文書）として保存される。サイトの登録情報は次回も使うため、レポートとは別の場所に保存する。どちらもGitでは共有されないので、必要なデータは自分たちの運用に合わせて保管する。

出力形式は「HTMLでも出して」「PDFにして」のように依頼できる。希望を保存すれば、次回からはその形式にも自動で変換する。希望が未登録なら初回に聞かれ、形式を決めずに進めた場合はMarkdownのみになる。今回だけ別の形式が必要な場合は、その旨を伝える。作成済みの文書も「このレポートをHTMLにして」と頼める。PDFは初回に追加のダウンロードが必要なため、AIが準備を案内する。

### レポートの一覧を見る

作成したレポートは`outputs/`内のサイト別フォルダにある`index.html`へ一覧で表示される。この一覧は各作業の完了時に自動で更新される。

一覧を見たいときは、AIに「レポートの一覧ページの場所を教えて」と頼み、案内された`index.html`をブラウザで開く。一覧を更新したいときも「レポートの一覧を更新して」と頼める。

Googleドキュメント・スプレッドシートに書き出したい場合は [docs/setup-google-output.md](docs/setup-google-output.md)（任意設定）を参照する。

## 困ったとき

- `git`や`uv`が見つからない場合は、[手順1（必要なツールをインストールする）](#install-tools)を確認し、PowerShell／ターミナルとAIツールを開き直す
- AIがファイルを読めない場合は、手順3（AIエージェントでフォルダを開く）で選んだフォルダを確認する
- 分析中に止まったら、AIに「どこまで完了したか、次に何をすればよいか教えて」と頼む
- GA4/GTMの認証エラーで詰まったら [docs/setup-ga4.md](docs/setup-ga4.md) の「うまくいかないときの見分け方」を確認する
- Search Consoleのデータが基本分析に出ない場合は [docs/setup-search-console.md](docs/setup-search-console.md) の権限付与と動作確認を確認する
- データの取り扱い（どこにも勝手に送信していないか）は [docs/data-handling.md](docs/data-handling.md) を参照
- 詳しい実行ルールは[標準実行順序](docs/standard-run-order.md)にある。主にAIが読む手順書なので、初めから全部読む必要はない

## 複数サイトを見たい場合

別のサイトを分析するときは、そのサイト用にもう1つコピーする。PowerShell／ターミナルで次を実行する。`another-site`は新しく作るフォルダ名の例なので、サイトごとに違う名前に置き換える。

```bash
cd ~
git clone https://github.com/TigerMonday/super-access-analytics-public.git another-site  # leak-ok: 配布元
```

新しいフォルダをAIで開き、同じ導入手順で対象サイトへの接続と登録を行う。サイトの登録情報はコピー間で共有されない。鍵はコピーの外に置くため、すでにある鍵で新しいサイトを読める場合は作り直さず、接続先を確認して使う。1つのコピー内に複数サイトの情報を混ぜない。
